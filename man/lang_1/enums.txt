Enums and constants: enum types, bitfields, integer constants, and how Godot sees them

GD++ declares two things with `enum`: enum types, i.e. sets of named integer values, and integer constants of a class. Enum types in GD++ work a bit differently from enums in C++, Godot and GDScript: they're global types of the package.

# Enum types

```gd++
enum Suit {
  DIAMONDS
  CLUBS
  SPADES
  HEARTS
}

enum Rank { JACK = 11, QUEEN, KING, ACE = 1 }
```

`enum Name { ... }` holds the values: names, each with an optional value after `=`. Separate them with spaces, newlines or commas. A comma after the last one is fine. A value without `=` is the previous value plus one, and the first one is 0. So `JACK` is 11, `QUEEN` 12, `KING` 13 and `ACE` 1. Bitfields count differently: see "Bitfields" below.

Values are integers that fit in 64 bits, written as decimal, negative, hexadecimal, binary or octal numbers, with optional digit separators. See `gd++ man syntax`. Two values of an enum can't have the same name, but they can have the same number.

```gd++
enum Flags {
  NONE = 0
  VISIBLE = 0x1
  SOLID = 0x2
  ALL = 0x3
}
```

A value can also be a value of another enum, whose number GD++ copies. Write it like in GD++, `Enum.VALUE`, for a GD++ enum or an engine enum, or like in GDScript, `Class.CONSTANT`, for an engine enum of a class:

```gd++
enum MyShadowSetting {
  OFF = GeometryInstance3D.SHADOW_CASTING_SETTING_OFF
  ON = GeometryInstance3D.ShadowCastingSetting.ON
  DOUBLE_SIDED
  HARD = Level.HARD
  ALSO_ON = ON
}
```

In GD++, the values of an engine enum leave out the prefix that comes from the enum's name, so that, like the values of GD++ enums, they have none: `GeometryInstance3D.ShadowCastingSetting`'s `SHADOW_CASTING_SETTING_ON` is `ON`, and `Node.ProcessMode`'s `PROCESS_MODE_INHERIT` is `INHERIT`. A value keeps its full name if the rest isn't a name, e.g. `Key`'s `KEY_3`, or is the name of another value of the enum. `Error`'s values keep theirs, e.g. `OK` and `ERR_BUSY`, since they don't start with `ERROR_`.

So `GeometryInstance3D.ShadowCastingSetting.SHADOW_CASTING_SETTING_OFF`, which mixes the two spellings, is an error. Global engine enums, e.g. `Error`, only have the GD++ spelling: `Error.OK`.

A value of the enum itself is written with or without the enum's name, `ON` or `MyShadowSetting.ON`, and must come before the value that uses it. A value without `=` counts on from the value before it, as usual: `DOUBLE_SIDED` is 2.

Values combine with operators, like in C++ and GDScript. From the ones that bind tightest to the loosest:

- `~` (bitwise not) and `-` (negation),
- `*` (multiplication), `/` (division) and `%` (remainder),
- `+` (addition) and `-` (subtraction),
- `&` (bitwise and),
- `^` (bitwise xor),
- `|` (bitwise or).

Parentheses group, and operators of the same level go from left to right. So `A | B & C` is `A | (B & C)`, and `A - B - C` is `(A - B) - C`. They work on 64-bit integers like in GDScript: `~0` is -1, division rounds toward zero, so `-7 / 2` is -3 and `-7 % 2` is -1, and results that don't fit wrap around. Dividing by zero is an error. A value ends where no operator continues it, so `A = B | C D` holds two values, `A` and `D`.

```gd++
enum Letter {
  A = 65
  Z = A + 25
  LOWER_A = A | 0x20
  LOWER_Z = Z | 0x20
}

enum Speed {
  SLOW = 10
  FAST = SLOW * 3
  AVERAGE = (SLOW + FAST) / 2
}
```

In ASCII, setting the bit 0x20 of a capital letter makes it lowercase, so `LOWER_A` is 97, the code of "a". For values that are sets of flags, don't write the powers of two by hand: use a bitfield, which counts them for you. See "Bitfields" below.

Each value can have a doc comment, which Godot's help shows. See `gd++ man docs`.

```gd++
enum Weather {
  /// Clear sky.
  SUNNY
  /// Rain, which makes roads slippery.
  RAINY
}
```

# A global type

A GD++ enum is a type of the whole package: every GD++ file of the package can use it, wherever it's declared. It can be declared:

- at the top level of a file, next to inline classes,
- inside a class, file-level or inline, which changes nothing about its scope,
- as a whole file, with `enum_name`. See `gd++ man files`.

Its name must be unique in the package, like the names of classes and externs.

```gd++
enum_name Suit
DIAMONDS
CLUBS
SPADES
HEARTS
```

# Extending enums

```gd++
enum Suit { DIAMONDS, CLUBS, SPADES, HEARTS }

enum TarotSuit {
  extends Suit
  TRUMPS
}

enum Mode {
  extends Node.ProcessMode
  EDITOR
}
```

`extends Base`, first in the braces, makes an enum copy all the values of `Base`, with their GD++ names, as if they were written before its own. `Base` is a GD++ enum of the package, or an engine enum: either one of a class, e.g. `Node.ProcessMode`, or a global one, e.g. `Error`. The values of engine enums come from the package's API spec, and their GD++ names leave out the enum's prefix, as explained above. So `Mode` has `INHERIT`, `PAUSABLE`, `WHEN_PAUSED`, `ALWAYS`, `DISABLED` and `EDITOR`. The values of a GD++ base keep their names exactly, prefix or not.

A value without `=` is the previous value plus one, so the first own value counts on from the base's last one: `TRUMPS` is 4, and `EDITOR` is 5, after `DISABLED = 4`. The own flags of a bitfield start above all of its base's values instead: see "Bitfields" below.

The result is an enum like any other: in C++, a new enum class, e.g. `Mode::INHERIT`, and in Godot, an enum of each class that exposes it, e.g. `Board.MODE_INHERIT`. A global enum needs a new name, e.g. `enum KeyCode { extends Key }`, since Godot's names are taken.

With `enum_name`, `extends` goes on the line after the name:

```gd++
enum_name TarotSuit
extends Suit
TRUMPS
```

# Bitfields

```gd++
@bitfield
enum Layer {
  NONE = 0
  WORLD
  PLAYER
  ENEMY
  ACTORS = PLAYER | ENEMY
}
```

`@bitfield` makes an enum a bitfield: a set of flags, which a value can combine. Its values without `=` are the flags: powers of two, starting at 1. So `WORLD` is 1, `PLAYER` 2, `ENEMY` 4, and `ACTORS` 6.

The flags must be next to each other. Values with `=` can come before them, e.g. `NONE`, or after them, e.g. `ACTORS`, but not between them. The largest flag is 2^62, so a bitfield has at most 63 flags.

A bitfield can only extend a bitfield, and an enum only an enum. The first own flag of a bitfield that extends another is the smallest power of two above the base's values:

```gd++
@bitfield
enum GameLayer {
  extends Layer
  PICKUP
}

@bitfield
enum MySizeFlags {
  extends Control.SizeFlags
  HUGE
}
```

`PICKUP` is 8, after `ACTORS = 6`, and `HUGE` is 16, after `Control.SizeFlags`'s `SIZE_SHRINK_END = 8`.

In C++, a bitfield is an enum class like any other (see "In C++" below), with the operators `|`, `&`, `^`, `~`, `|=`, `&=` and `^=`, so values combine without casts. Test a flag by comparing:

```gd++
@export var mask: Layer = WORLD | PLAYER

func hits_enemies() -> bool {
  return (mask & Layer::ENEMY) != Layer::NONE;
}

func add(layers: Layer = ENEMY) -> void {
  mask |= layers;
}
```

An initial value or a default value of a bitfield type can combine the bitfield's values with `|`, `&`, `^`, `~` and parentheses without C++: `WORLD | PLAYER` stands for `Layer::WORLD | Layer::PLAYER`.

Godot sees a bitfield as a bitfield of each class that exposes it, like `Control.SizeFlags`: in GDScript, its type is e.g. `BitField[Table.Layer]` for a class `Table`, and the help marks it as one. An exported variable of a bitfield type shows a checkbox for each value that is a single flag. See `gd++ man exports`.

# In C++

Each enum becomes a C++ enum class with `int64_t` values, in namespace `godot`, in its own header, e.g. `Suit.h`:

```cpp
enum class Suit : int64_t {
  DIAMONDS = 0,
  CLUBS = 1,
  SPADES = 2,
  HEARTS = 3,
};
```

So values are scoped: write `Suit::HEARTS` in C++ code. Convert to and from integers with `as` (see `gd++ man cast`):

```gd++
var trump: Suit = Suit::HEARTS

func trump_index() -> int {
  return trump as int64_t;
}

func set_trump_index(i: int) -> void {
  trump = i as Suit;
}
```

GD++ includes the enum's header wherever it's used.

An initial value or a default value of an enum type can name one of the enum's values, without C++: `HEARTS` or `Suit.HEARTS` stands for `Suit::HEARTS`. For a bitfield, it can also combine them: see "Bitfields" above. Anything else is C++, as usual.

```gd++
var trump: Suit = HEARTS

func deal(suit: Suit = Suit.SPADES) -> void { ... }
```

An enum and its base are different C++ types, even with the same values: convert between them with `as`. Redeclaring an engine enum is how GD++ code uses it as a type:

```gd++
enum ShadowCastingSetting { extends GeometryInstance3D.ShadowCastingSetting }

@export var casting: ShadowCastingSetting = ON

func _ready() -> void {
  mesh->set_cast_shadows_setting(casting as GeometryInstance3D::ShadowCastingSetting);
}
```

# In Godot

Godot has no global enums for extensions: every enum belongs to a class, e.g. `Node.ProcessMode`. So GD++ gives each class that needs an enum its own copy of it. A class exposes an enum if:

- it uses the enum in its API: as the type of a variable, a parameter or the return value of a function (except `@override` functions), or a parameter of a signal,
- it imports the enum, with `import Suit`,
- the enum is declared inside it,
- it's a file-level class, and the enum is declared anywhere in its file.

`noimport Suit` stops a class from exposing the enum. `noimport` is an error if the class uses the enum in its API, since Godot must know the enum then.

A class exposes an enum, bitfields included, as integer constants of the class, named after the enum and the value, in UPPER_SNAKE_CASE: `Suit`'s `HEARTS` becomes `SUIT_HEARTS`, and `HTTPCode`'s `NOT_FOUND` becomes `HTTP_CODE_NOT_FOUND`. They belong to an enum of the class named like the GD++ enum, e.g. `Table.Suit`. In GDScript:

```gdscript
var s: Table.Suit = Table.SUIT_HEARTS
table.play(Table.SUIT_SPADES)
```

In the editor's help, the values are listed under the class's constants, and variables, parameters and return values of the enum's type show as `int`, with the enum's name. An exported variable of an enum type shows a drop-down list of the values. A bitfield is marked as a bitfield instead, and an exported variable shows checkboxes: see "Bitfields" above, and `gd++ man exports`.

Two classes that expose the same enum have equal values: `Table.SUIT_HEARTS == Deck.SUIT_HEARTS`.

# How it's done

Functions, variables and signals whose types use an enum are bound through a stand-in type per class and enum, named `_gdpp_<Class>_<Enum>`, e.g. `_gdpp_Table_Suit`, which Godot sees as the enum `Table.Suit`, or for a bitfield, as the bitfield `Table.Suit`. Wrappers named `_gdpp_` followed by the name of the function, getter or setter convert between the stand-in and the real enum. Your code never sees them: it uses `Suit`. See `gd++ man generated`.

# Integer constants

```gd++
class_name Game
extends Node

enum MAX_PLAYERS = 4
enum START_LIVES = 3
```

`enum NAME = VALUE`, inside a class, declares an integer constant of the class. In C++, it's a `static constexpr int64_t` member, e.g. `MAX_PLAYERS` or `This::MAX_PLAYERS`, and in Godot, an integer constant of the class, e.g. `Game.MAX_PLAYERS` in GDScript.

Unlike enum types, constants belong to their class: they can only be declared inside a class, and share its namespace with functions and variables. GDExtensions can only expose integer constants to Godot, so GD++ only has integer constants, and has no `const` keyword. For constants of other types, use a `@static` function, or a `static constexpr` member in a `decl` block:

```gd++
@static
func gravity() -> Vector3 {
  return Vector3(0, -9.8, 0);
}

decl {
  static constexpr double PI_2 = 6.28318530718;
}
```

Constants take a doc comment, but no annotations.

# Rules

- Enum types take only `@bitfield`, and constants take no annotations.
- An integer constant outside a class is an error: "This enum is outside of any class.".
- A value that isn't an integer, a value of an enum, or those combined with operators is an error, e.g. `A = 1.5` or `A = 1 +`. So is dividing by zero.
- A value of an unknown enum, or an unknown value, is an error, and so is an enum that depends on itself through its values.
- A value of an engine enum must use one spelling: `GeometryInstance3D.ShadowCastingSetting.OFF` or `GeometryInstance3D.SHADOW_CASTING_SETTING_OFF`, not `GeometryInstance3D.ShadowCastingSetting.SHADOW_CASTING_SETTING_OFF`.
- An enum can't extend itself through its bases, a class, or an unknown name, and its own values can't have the names of inherited ones.
- `extends` must come before the values: `enum A { X extends Suit }` is an error.
- A bitfield's values without `=` must be next to each other, and a bitfield can't have more than 63 flags.
- A bitfield can't extend an enum, and an enum can't extend a bitfield.
- An enum can't be the base of a class, nor an element type of `Array[T]` or `Dictionary[K, V]`: use `int` there.
