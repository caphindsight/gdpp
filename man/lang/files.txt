Files: what a GD++ file declares, and how it's laid out

A GD++ file declares classes, externs and enums. It can declare several of them, and every other GD++ file of the package can use them. This page explains the layout of a file: file-level and inline declarations, and what goes where.

# File-level and inline declarations

Each kind of declaration comes in two forms:

```gd++
class_name Player        // file-level: the rest of the file is the class
class Enemy { ... }      // inline: the braces hold the class

extern_name Terrain      // a file-level extern
extern Road { ... }      // an inline extern

enum_name Suit           // a file-level enum: the rest of the file is its values
enum Rank { ... }        // an inline enum
```

Both forms work the same. The file-level form saves a level of braces and indentation, like in GDScript, where a file is a class. A file has at most one file-level declaration, and it must come first, before anything else except comments.

# A file-level class

```gd++
class_name Player
extends CharacterBody3D

var speed: float = 5.0

func jump() -> void {
  // ...
}
```

class_name NAME starts the file. extends, if any, comes right after it, even on the same line: `class_name Player extends CharacterBody3D`. Everything after it, to the end of the file, is a member of the class, except inline classes and externs, which can appear between members:

```gd++
class_name Player
extends Node

var a: int          // a member of Player

class Weapon {      // an inline class
  var damage: int
}

var b: int          // still a member of Player
```

This is the usual layout: one main class per file, with small helper classes next to it.

# A file-level extern

```gd++
extern_name Terrain
extends Node3D

func height_at(x: float, z: float) -> float
signal changed
```

Like class_name, but for an extern: the rest of the file declares its members. Inline classes and externs can appear between them. See `gd++ man externs`.

# A file-level enum

```gd++
enum_name Suit
DIAMONDS
CLUBS
SPADES = 10
HEARTS
```

enum_name NAME makes the whole file an enum: everything after it is a value of that enum. Nothing else can follow, not even inline classes. It's rarely used, but exists for consistency. The file then declares no classes, so it adds nothing to Godot by itself, but every GD++ file of the package can use the enum. See `gd++ man enums`.

# A file without a file-level declaration

A file can also have only inline declarations:

```gd++
class Enemy {
  extends Node3D
  var health: int
}

class Boss {
  extends Enemy
}

enum Difficulty { EASY NORMAL HARD }

extern Terrain {
  extends Node3D
}
```

At its top level, such a file can only have inline classes, inline externs and inline enums. Anything else, e.g. a func, a var, an integer constant or a decl block, belongs in a class:

```out
[×] res://enemies.gd++:12:1: This func is outside of any class.
     12 | func spawn() -> void {}
        | ^^^^
    Hint: Add "class_name Name" at the top of the file to make the whole file a class, or move this into an inline class: "class Name { ... }".
```

# No nesting

Classes and externs can't be nested: an inline class can't be inside another class or extern, even a file-level one's braces. They're all listed next to each other. Enums can be declared inside a class, but they are global types anyway. See `gd++ man enums`.

# Order

The order of declarations in a file doesn't matter: a class can extend a class declared further down, and use types declared anywhere in the package. GD++ generates the files in the order of the declarations, and registers classes after their base classes.

# Names

Every class, extern and enum has a name, which must be unique in the package: two GD++ files can't declare the same name, and a name can't be declared twice in one file. Names must also differ from Godot's classes and from godot-cpp's names, e.g. Node or TypedArray.

The name of a class or enum becomes the name of its generated files, e.g. Player.h and Player.cpp, and the name of the class in Godot. It doesn't need to match the file's name: player.gd++ can declare Player, or anything else.

# One file, many outputs

Each declaration generates its own files, as if it were alone in its file: a class generates NAME.h and NAME.cpp, an extern and an enum generate NAME.h. The declarations of one file see each other just like they see the declarations of other files. See `gd++ man generated`.

# Example: a typical file

```gd++
/// A card game's table.
class_name Table
extends Node2D

enum Suit { DIAMONDS CLUBS SPADES HEARTS }

signal card_played(suit: Suit, rank: int)

var cards: Array[Card]

func play(card: Card) -> void {
  cards.erase(card);
  emit card_played(card->get_suit(), card->get_rank());
}

/// A playing card.
class Card {
  extends Resource
  @export var suit: Suit
  @export var rank: int
}
```
