Generated code: the C++ that GD++ writes, file by file

GD++ turns each GD++ file into ordinary C++, which you can read, debug and include. This page describes that C++ in detail: which files there are, what's in them, and the names of the helpers GD++ adds. To see the C++ of a file, run `gd++ trans FILE`; in a build, it's in the package's build cache, in .gd++pkg/gdpp. See `gd++ man trans` and `gd++ man build-cache`.

# Files

Each declaration of a GD++ file gets its own files, named after it:

- a class NAME: NAME.h, its definition, and NAME.cpp, its methods and bindings,
- an extern NAME: NAME.h, its wrapper class,
- an enum NAME: NAME.h, its enum class.

Plus, for the whole package:

- gd++/syntax_0.hpp, the runtime header. See `gd++ man runtime`.
- doc_classes/NAME.xml per class, its documentation, in debug builds. See `gd++ man docs`.

Every generated file starts with "// Generated by GD++ from FILE, do not edit.". Headers use #pragma once, and everything is in namespace godot, except @global blocks.

# An example

counter.gd++:

```gd++
class_name Counter
extends Node

signal changed(value: int)

var count: int = 1

func add(amount: int = 1) -> void {
  count += amount;
  emit changed(count);
}
```

# The class header

In order:

1. The #include lines: the runtime header, then the headers of the names the header uses, sorted. See `gd++ man includes`.
2. @global decl blocks.
3. In namespace godot: forward declarations of the package's GD++ classes, externs and enums that the header uses, e.g. `class Enemy;` or `enum class Suit : int64_t;`.
4. The enum stand-ins of the class, one per enum it exposes: `enum _gdpp_Counter_Suit : int64_t {};` and GDPP_ENUM_TAG, or GDPP_BITFIELD_TAG for a bitfield. See `gd++ man enums`.
5. The class, between `#define This NAME` and `#undef This`:
   - GDCLASS(NAME, BASE),
   - each decl block, after `private:`,
   - `public:` the fields of simple variables, value-initialized with {},
   - `private:` the decl blocks of properties,
   - `public:` integer constants as static constexpr int64_t, the constructor and destructor if any, GDVIRTUAL declarations of @virtual functions, the functions, RPC helpers, getters and setters, and the emit functions of signals,
   - `protected:` static void _bind_methods(),
   - `private:` the generated helpers: enum wrappers, and default value functions.
6. The #include lines of the GD++ names that were only forward-declared, at the end, after namespace godot.

# The class source

In order:

1. #include "NAME.h", then the headers of names that only the source uses.
2. @global impl blocks.
3. In namespace godot, between `#define This NAME` and `#undef This`:
   - _bind_methods: binds each function (with its default values), each variable's getter and setter and its property (after the inspector sections it starts), each signal, each integer constant, and each value of each exposed enum (as a bitfield flag for a bitfield),
   - the constructor, if needed: RPC configurations, set_process(true) and set_physics_process(true) for overrides, the initial values of variables, then the ctor block. See `gd++ man lifecycle`.
   - the destructor, with the dtor block,
   - each function: the editor check if the class isn't @tool, the GDVIRTUAL_CALL of a @virtual function, the @onready initial values in _ready, then the body (or for @deferred and @thread_safe, the call that runs _gdpp_body_NAME later); then its enum wrapper, default value functions and RPC helper,
   - each variable's getter and setter, and their enum wrappers,
   - each signal's emit function,
   - the impl blocks.

# Generated names

GD++ names its helpers with the prefix _gdpp_, which is reserved: don't use it for your own names.

```
get_NAME, set_NAME           a variable's getter and setter
NAME (of a signal)           a signal's emit function, returning gdpp::Emitted
_gdpp_default_FUNC_PARAM     a static function that returns a parameter's default value
_gdpp_rpc_FUNC               an @rpc function's helper, which rpc and rpc_id call
_gdpp_body_FUNC              the body of a @deferred or @thread_safe function, which its deferred call runs
_gdpp_FUNC                   the wrapper that binds a function with enums in its signature
_gdpp_get_NAME, _gdpp_set_NAME   the wrappers that bind a variable of an enum type
_gdpp_CLASS_ENUM             a class's stand-in type for an enum
_gdpp_ret                    a local variable in @virtual functions
_gdpp_base                   an extern wrapper's object
```

This is a macro, defined around each class's code. The setter's parameter is p_value, unless a property's set block names it.

# #line directives

Every piece of your code, e.g. a function body or an initial value, is wrapped in #line directives: one before it, with its line in the GD++ file, and one after it, which switches back to the generated file. So compiler errors, warnings and debuggers point to the right line in the right file. In builds, the GD++ file is named relative to the build cache, e.g. ../src/player.gd++.

Your code is copied with its line breaks, so a body's text starts on the line of its "{".

# Extern headers

An extern NAME gets a header with a wrapper class NAME, in namespace godot:

```cpp
class Terrain {
public:
  using Base = Node3D;
  static constexpr const char *gdpp_name = "Terrain";
  explicit Terrain(Base *p_object);
  double height_at(double x, double z) const;
  int64_t get_seed() const;
  void set_seed(int64_t p_value) const;
  gdpp::Emitted changed() const;
protected:
  Base *_gdpp_base;
};
```

Its methods are defined inline, after the classes they may use, and call _gdpp_base->call, call_deferred, get, set or emit_signal with the member's name. See `gd++ man externs`.

The wrapper of an extern that extends another extern derives from that one's wrapper, e.g. `class Car : public Vehicle`, and shares its Base and _gdpp_base.

# Enum headers

An enum NAME gets a header with an enum class:

```cpp
enum class Suit : int64_t {
  DIAMONDS = 0,
  CLUBS = 1,
  SPADES = 2,
  HEARTS = 3,
};
```

A bitfield's enum class is followed by `GDPP_BITFIELD(Name)`, which gives it the bitwise operators.

# Registration

The build also generates __register_types__.cpp, in the build cache, outside gdpp/. It includes every class's header, and registers each class when the library loads, bases first, with GDREGISTER_RUNTIME_CLASS for GD++ classes without @tool, and GDREGISTER_CLASS for the others. Its entry point is gdpp_library_init. See `gd++ man cpp-classes`.

# Using generated classes from C++

Plain C++ files of the package can include a GD++ class's header, e.g. #include "Counter.h", and use the class: its functions, getters and setters are public methods, and the fields of simple variables are public too.
