Functions: func, parameters, default values, and @override, @virtual, @const, @static

A function is a method of its class that Godot knows: GDScript can call it, e.g. player.jump(), and so can call(), signals and the editor. Its signature is GD++; its body is C++.

# Syntax

```gd++
func greet(name: String, times: int = 1) -> void {
  for (int64_t i = 0; i < times; i++) {
    gd::print("Hello, ", name, "!");
  }
}
```

- func, then the name, then the parameters in parentheses, separated by commas. A trailing comma is allowed.
- Each parameter is `name: Type`, or just `name` for a Variant, with an optional default value after "=".
- Then, optionally, "->" and the return type. Without it, the function returns a Variant.
- Then the body: C++ code in braces. The body is optional.

In the body, parameters have their C++ types: here, name is a const String & and times an int64_t. See `gd++ man types`.

```gd++
func area(width: float, height: float) -> float {
  return width * height;
}

func describe(value) -> String {        // value is a Variant
  return String("Got: ") + String(value);
}

func random_thing() {                   // returns a Variant
  return Variant(42);
}
```

# Functions without a body

```gd++
func not_done_yet() -> int
```

A function without a body gets a generated one, which returns the type's default value: 0, false, an empty String, nullptr, and so on; or nothing, for void. It's handy for @virtual functions, and to sketch a class's API.

# What GD++ does with a function

- It declares the function as a public method of the C++ class, and defines it in the class's source file, with your body.
- It binds the function in _bind_methods with ClassDB::bind_method, with its parameter names and default values, so Godot can call it. @static functions are bound with ClassDB::bind_static_method, @virtual ones with GDVIRTUAL_BIND, and @override ones not at all, since the engine binds them.
- In a class without @tool, the body starts with a check that returns right away in the editor, in debug builds. See `gd++ man classes`.

Functions are plain C++ methods, so C++ code calls them directly, e.g. `jump();` or `player->jump();`, at full speed.

Function names must be unique in their class, including the getters and setters of variables and the emit functions of signals: there is no overloading.

# Default values

```gd++
func spawn(count: int = 1, at: Vector3 = Vector3(0, 1, 0), kind: Kind = Kind::BIG) -> void { ... }
```

A default value is a C++ expression, up to the "," or ")" that ends it, or a block of C++ that returns the value:

```gd++
func shout(text: String = {
  return String("HEY").repeat(3);
}) -> void { ... }
```

For a parameter of a GD++ enum type, the default value can also be one of the enum's values, e.g. `suit: Suit = HEARTS`. See `gd++ man enums`.

Parameters with default values must come last:

```out
[×] res://a.gd++:4:20: Parameter b needs a default value, since a parameter before it has one.
     4 | func f(a: int = 1, b: int) -> void {}
       |                    ^
    Hint: Parameters with default values must come last.
```

GD++ puts each default value into a static method of the class. Godot calls it once, when it registers the class, and uses the result whenever GDScript leaves the parameter out. C++ callers get the default values too, since the C++ declaration uses them. Since the default is computed in a static method, it can't use the object (this) or the other parameters.

The editor's help shows a default value as written, if it's an expression rather than a block.

# @override

```gd++
@override
func _ready() -> void {
  gd::print("Ready.");
}

@override
func _process(delta: float) -> void {
  rotate_y(delta);
}
```

@override overrides a virtual function of the engine, i.e. of the base class, e.g. _ready, _process, _physics_process, _input, _unhandled_input, _enter_tree, _exit_tree, _draw or _get_configuration_warnings. The engine calls it, like in GDScript.

The signature must match the engine's exactly, in C++ terms, including the return type: without `-> void`, the function returns a Variant, and the C++ compiler reports that it doesn't override anything. Use `gd++ doc Node._process` to see a signature. A const engine function, e.g. _get_configuration_warnings, needs @const too: `@const @override`. Note that the engine's float parameters are double, like GD++'s float.

Overrides are not bound, since the base class binds them already. GD++ also does two things for you:

- Overriding _process or _physics_process turns processing on in the constructor, with set_process(true) or set_physics_process(true), since godot-cpp doesn't do so on its own.
- Overriding _ready runs the initializers of @onready variables at its start, before your code. See `gd++ man lifecycle`.

# @virtual

```gd++
@virtual
func _can_pick(item: Item) -> bool {
  return true;
}

@virtual
func _on_hit(damage: int) -> void
```

@virtual declares a function that scripts can override, like the engine's own virtual functions. A GDScript that extends the class overrides it by defining a function of the same name:

```gdscript
extends Player

func _can_pick(item):
    return item.price < 10
```

When C++ code calls the function, the script's version runs if a script overrides it; otherwise the body runs, as a fallback, or without a body, the type's default value is returned. By convention, virtual functions start with an underscore.

@virtual generates a GDVIRTUAL declaration and binds it with GDVIRTUAL_BIND, and the editor's help marks the function "virtual".

# @const

```gd++
@const
func is_alive() -> bool {
  return health > 0;
}
```

@const makes the function a const method in C++: it can't change the object's fields, and can be called through const pointers and references. The editor's help marks it "const". Combine it with @virtual for a const virtual function.

# @static

```gd++
@static
func lerp_angle(from: float, to: float, weight: float) -> float {
  return Math::lerp_angle(from, to, weight);
}
```

@static makes the function static: it belongs to the class, not to an object, so it has no this, and can't use the object's fields. GDScript calls it on the class: Player.lerp_angle(0, 1, 0.5).

# @rpc

@rpc makes the function callable over the network. See `gd++ man rpc`.

# Combining attributes

Attributes can be combined where it makes sense, e.g. @virtual @const. These combinations are errors:

```
@static with @virtual, @override, @const or @rpc
@virtual with @override or @rpc
@override with @rpc
```

Each attribute can be used once per function. They take no arguments, except @rpc.

# Enums in signatures

A function whose parameters or return type use a GD++ enum is bound through a generated wrapper, named _gdpp_ and the function's name, which converts between the enum and the class's own copy of it that Godot sees. Your function keeps the plain enum type. See `gd++ man enums`.

# Doc comments

```gd++
/// Deals [param damage] to the player.
/// Returns [code]true[/code] if the player died.
func hurt(damage: int) -> bool { ... }
```

A doc comment before a function becomes its description in the editor's help. Annotations and the doc comment can be in any order. See `gd++ man docs`.

# Examples

```gd++
class_name Inventory
extends Node

var items: Array[Item]

/// Adds an item, unless the inventory is full.
func add(item: Item, max_size: int = 20) -> bool {
  if (items.size() >= max_size) {
    return false;
  }
  items.push_back(item);
  return true;
}

@const
func total_price() -> int {
  int64_t total = 0;
  for (int64_t i = 0; i < items.size(); i++) {
    Ref<Item> item = items[i];
    total += item->get_price();
  }
  return total;
}

@static
func max_items() -> int {
  return 20;
}

@virtual
func _accepts(item: Item) -> bool {
  return true;
}
```
