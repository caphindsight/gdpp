Classes: declaring Godot classes, bases, @tool and @icon

A GD++ class is a Godot class, like Node3D or Resource: once built, it shows up in the editor's "Create New Node" dialog (or the resource list), GDScript can use it, and it can be the base of scripts. This page explains how to declare classes, and what GD++ makes of them.

# Declaring a class

A file-level class takes the rest of the file:

```gd++
class_name Player
extends CharacterBody3D

var speed: float = 5.0
```

An inline class takes a pair of braces, and extends goes first inside them:

```gd++
class Bullet {
  extends Area3D
  var damage: int = 10
}
```

Both are the same kind of class. A file can have one file-level class and any number of inline classes. See `gd++ man files`.

# Base classes

extends names the base class. It can be:

- a Godot class, e.g. Node, Node3D, Resource or Object, from the package's API spec,
- another GD++ class of the same package, from any file.

Without extends, the class extends RefCounted, like in GDScript.

```gd++
class_name Enemy
extends CharacterBody3D

class Boss {
  extends Enemy        // another GD++ class
}

class Stats {}          // extends RefCounted
```

A class can't extend an extern, an enum, a C++ class of the package, or itself through its bases:

```out
[×] res://a.gd++:2:9: A can't extend Terrain, which is an extern.
     2 | extends Terrain
       |         ^^^^^^^
    Hint: Extend the extern's base class instead.
```

# Objects and references

Godot has two kinds of classes, and GD++ uses them differently in C++:

- Refcounted classes: RefCounted and every class that extends it, e.g. Resource, Texture2D or your class Stats above. Godot deletes their objects when the last reference goes away. In C++, GD++ types them as Ref<Stats>.
- Other classes: Object and every class that extends it but not RefCounted, e.g. Node and all nodes. You delete their objects yourself, e.g. with queue_free() or memdelete(). In C++, GD++ types them as pointers, e.g. Player*.

A GD++ class is refcounted if its base is. See `gd++ man types`.

In C++ code, create objects of your classes like those of any Godot class:

```gd++
Bullet *bullet = memnew(Bullet);           // an object
add_child(bullet);

Ref<Stats> stats;                          // a refcounted object
stats.instantiate();
```

In GDScript, use them like built-in classes: Bullet.new(), `var s: Stats`, `extends Player`, and so on.

# @tool

Like in GDScript, the code of a class runs in the editor only if the class has @tool:

```gd++
@tool
class_name Gizmo
extends Node3D

@override
func _process(delta: float) -> void {
  rotate_y(delta);          // Spins in the editor too.
}
```

Without @tool, a class is a runtime class:

- It's registered with Godot as a runtime class. In the editor, Godot creates placeholders for its objects: they store their property values, which you set in the inspector, but run none of the class's code.
- In debug builds, which the editor loads, each of its functions starts with a check that returns right away, with a default value, when called in the editor.

So a runtime class can't break the editor, e.g. by moving nodes around in a scene you're editing. Games run from the editor, and exported games, run all code. Inline classes need their own @tool: it's not inherited from the file-level class, nor from the base class.

`gd++ ls` shows @tool classes as "GD++ @tool".

# @icon

```gd++
@icon("res://icons/player.svg")
class_name Player
extends CharacterBody3D
```

@icon sets the class's icon in the editor, e.g. in the scene tree and the "Create New Node" dialog. It takes one argument, a string with the path of the icon, usually an SVG file. The path must start with res://, relative to the project, or pkg://, relative to the package:

```gd++
@icon("pkg://icons/bullet.svg")
class Bullet {
  extends Area3D
}
```

GD++ writes the icons into the package's .gdextension file. A missing icon file is shown in red by `gd++ ls`.

# Annotations and doc comments

A class can have @tool and @icon, in any order, and a doc comment, before class_name or class:

```gd++
/// The player's character.
///
/// It runs, jumps and collects coins.
@tool
@icon("res://icons/player.svg")
class_name Player
extends CharacterBody3D
```

The first paragraph of a class's doc comment is its brief description, and the rest its full description. See `gd++ man docs`.

# Members

A class body holds members, in any order:

```
func       functions                      gd++ man functions
var        variables and properties       gd++ man variables
signal     signals                        gd++ man signals
enum       enums and integer constants    gd++ man enums
ctor       the constructor                gd++ man lifecycle
dtor       the destructor                 gd++ man lifecycle
decl, impl plain C++                      gd++ man code
import     force an include               gd++ man includes
noimport   prevent an include             gd++ man includes
```

Functions, variables, signals and constants share one namespace, since they all become C++ members of one class:

- A var x also declares its getter get_x and its setter set_x.
- A signal s also declares a C++ method s, which emits it.

So `var x` and `func get_x()` can't be in the same class:

```out
[×] res://player.gd++:8:1: The name "get_x" is already used by another member.
     8 | func get_x() -> int {
       | ^^^^
    Hint: Members share one namespace. A var x also declares get_x and set_x, and a signal declares its emit function.
```

Names that start with _gdpp_ are reserved for code that GD++ generates.

# This

In the C++ code of a class, This is the name of the class, like Self in Rust:

```gd++
func clone() -> Player {
  This *copy = memnew(This);
  copy->speed = speed;
  return copy;
}
```

It's a macro that GD++ defines around the class's code. See `gd++ man code`.

# What GD++ generates

For a class Player, GD++ generates Player.h and Player.cpp:

```cpp
class Player : public CharacterBody3D {
  GDCLASS(Player, CharacterBody3D)
  ...
protected:
  static void _bind_methods();
};
```

in namespace godot, with all members, and _bind_methods, which binds them to Godot. The build registers the class when Godot loads the library, after its base class if that's a class of the package too. See `gd++ man generated`.

# Examples

A resource type, for data files edited in the inspector:

```gd++
/// An item that the player can pick up.
@icon("res://icons/item.svg")
class_name Item
extends Resource

@export var title: String
@export var price: int
@export var icon: Texture2D
```

A node with a helper class:

```gd++
class_name Spawner
extends Node3D

@export var scene: PackedScene

func spawn() -> Node3D {
  Node3D *node = Object::cast_to<Node3D>(scene->instantiate());
  add_child(node);
  return node;
}

class SpawnInfo {
  var count: int
  var position: Vector3
}
```
