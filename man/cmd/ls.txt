gd++ ls: show an overview of the project

# Synopsis

```sh
gd++ ls [PATH] [--deps]
gd++ ls (-l | -a)
```

# Description

Prints an overview of the project: its name and settings, the dependencies in its caches, and its packages. The package that contains PATH, or the current directory, is expanded: its dependencies, settings and classes are shown. Other packages take one line each. If the project has only one package, it is always expanded.

It is the quickest way to check a project's state, e.g. after cloning it: it shows missing dependencies, unused dependencies, missing files, and GD++ files with errors.

# Options

PATH
  Expand the package containing this path. Default: the current directory.

--deps
  List every dependency in the caches, instead of counting them.

-l, --pkgs
  Expand all packages. Can't be used with PATH.

-a, --all
  Show all details: like --deps and --pkgs together. Can't be used with PATH.

# Output

```
Project: My Game [my_game]
  Godot:  4.7
  VCS:    git

Dependencies:
  Godot C++ bindings:  1 checked in  •  1 cached  •  1 unused
  Godot API specs:     1 cached
  Godot engines:       none

Package: res://gameplay
  Godot C++ bindings:  10.0.0-stable
  Godot API spec:      4.7.2-stable
  GD++ syntax:         1
  C++ standard:        c++20
  Class prefix:        Gameplay
  Quit timeout:        1 second

  C++ classes in the package
    Spinner  res://gameplay/spinner.h  @tool
  Classes in pkg://gizmo.gd++
    Gizmo  extends Node3D  @tool
  Classes in pkg://player.gd++
    Player  extends CharacterBody3D  @game_only @icon
    Stats   extends Resource         @icon (missing)
  pkg://broken.gd++: has errors, see gd++ build

Package: res://tools  missing dependencies

To fix: gd++ fetch --missing
```

The parts:

- Project: the name from project.godot, the project's id (its directory name) in brackets, the Godot version from project.godot, and the vcs setting from gd++proj.toml.
- Dependencies: per kind, how many are checked in, cached (in the ephemeral cache) and unused (named by no package). With --deps, one row per dependency, newest first, with its cache and whether it's unused.
- Package: the package's path, and for the root package, its id in brackets. An expanded package shows its bindings and spec, marked "missing" if the project doesn't have them, its GD++ syntax, marked "(nightly, not for production)" if it's 0, its C++ standard, class prefix and quit timeout (see `gd++ man packages`), and its classes.
- Classes: grouped by where they're declared. First the C++ classes from gd++pkg.toml, in order, each with its header. Then the classes of each GD++ file, in order, each with its base class. After each class, its tags: @tool (it runs in the editor too; without it, it's a runtime class), @game_only and @icon, from its annotations, or for a C++ class from gd++pkg.toml. Annotations for debugging, like @trace and @profile, aren't shown. A missing header or icon is marked "(missing)". A class declared twice is marked "declared twice". A GD++ file with errors gets a line of its own at the end, since its classes can't be read: run `gd++ build` or `gd++ trans` on it to see the error.

A collapsed package shows "missing dependencies" if it lacks any. If any package lacks dependencies, a hint at the end says how to fix it. Problems are shown in red.

On terminals without Unicode, "•" is "*".

The output goes to stdout, so you can save it or search it, e.g. `gd++ ls -a > overview.txt`.

# Examples

```sh
gd++ ls                  # the project, with the package you're in expanded
gd++ ls tools            # with res://tools expanded
gd++ ls -a               # everything
```
