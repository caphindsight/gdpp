Projects: Godot projects, gd++proj.toml, and what GD++ keeps in them

A GD++ project is just a Godot project: a directory with a project.godot file. There is nothing to convert. GD++ adds a few files and directories to it, all described on this page.

# What GD++ reads from project.godot

gd++ reads two settings from the [application] section of project.godot, which Godot writes:

- config/name: the project's name, shown by `gd++ ls`.
- config/features: the Godot version the project was made with, e.g. "4.3", shown by `gd++ ls`.

If either is missing, commands fail with "Failed to find the project name in res://project.godot." or "Failed to find the Godot version in ...". Open the project in the Godot editor once to fix this. gd++ never writes project.godot.

The project's id is the name of its root directory. The package at the project root is named after it too.

# gd++proj.toml

The project's GD++ settings live in res://gd++proj.toml. The file is optional: without it, every setting has its default. `gd++ init` without a path creates it:

```toml
vcs = "none"
```

vcs
  The version control system the project uses: "none" (the default) or "git". With git, GD++ keeps its blocks of ignores in the .gitignore files of the project and its packages. See `gd++ man vcs`.

Unknown keys are an error: "Unknown key ... in res://gd++proj.toml.". `gd++ fix` reformats the file to its canonical form.

# What GD++ adds to a project

```
res://
  project.godot        Godot's, not changed by GD++
  gd++proj.toml        the project's GD++ settings (optional)
  .gd++proj/           the ephemeral dependency cache
    bind/NAME/         Godot C++ bindings
    spec/NAME/         Godot API specs
    engine/NAME/       Godot engines
    temp/              temporary files of running commands
  _gd++proj/           the checked in dependency cache
    bind/NAME/  spec/NAME/  engine/NAME/
  some_package/        a package (any directory with a gd++pkg.toml)
    gd++pkg.toml
    .gd++pkg/          the package's build cache
    some_package.gdextension, .gdextension.uid, lib*.so/.dll/.dylib
```

The two dependency caches are explained in `gd++ man dependencies`, packages in `gd++ man packages`, and build caches in `gd++ man build-cache`.

gd++ creates directories only when it first needs them: a fresh project has none of them. It also deletes cache directories that become empty, e.g. when you remove the last dependency.

# Temporary files

Commands that download or unpack something, `gd++ fetch` and `gd++ vendor`, work in a random directory in res://.gd++proj/temp, and delete it when they finish, or fail. If gd++ is killed, e.g. with Ctrl+C, the directory may stay behind. `gd++ fix` deletes it.

# Many packages in one project

A project can have any number of packages, anywhere in it, even nested in each other, and at its root. Each builds into its own library. Commands that take --proj, e.g. `gd++ build --proj` and `gd++ clean --proj`, work on all of them. `gd++ ls` shows them all.

Packages in one project share the dependency caches, but each one chooses its own bindings and spec.

# Nested projects

A directory inside a project that has its own project.godot file is a separate project. gd++ doesn't look inside it when it works on the outer project, and commands run inside it work on it, not on the outer project.

# Example

A project with two packages:

```
my_game/
  project.godot
  gd++proj.toml        vcs = "git"
  .gitignore
  gameplay/
    gd++pkg.toml
    player.gd++
    enemy.gd++
  tools/
    gd++pkg.toml
    level_editor.gd++

cd my_game
gd++ init --vcs git                                              # creates gd++proj.toml
gd++ init gameplay --bind 10.0.0-stable --spec 4.7.2-stable
gd++ init tools --bind 10.0.0-stable --spec 4.7.2-stable
gd++ fetch --missing
gd++ build --proj
```
