The build tool: an overview

`gd++` is a small build system for Godot C++ code. Each part below has its own page, listed at the end.

# The pieces

- Project: a normal Godot project, i.e. a directory with a `project.godot` file. GD++ needs nothing more. See `gd++ man projects`.
- Package: a directory in the project with a `gd++pkg.toml` file.
  - It builds into one GDExtension library, from all its GD++ and C++ files.
  - A project has any number of packages, or just one at its root.
  - See `gd++ man packages`.
- Dependencies: big, versioned downloads that packages build with.
  - The Godot C++ bindings (godot-cpp).
  - The Godot API spec of the Godot version to target.
  - Each package names the ones it uses.
  - `gd++` downloads them into the project's caches. You can commit one of them.
  - See `gd++ man dependencies`.
- Build: turns a package into one library per target platform, and a `.gdextension` file that tells Godot where the libraries are. See `gd++ man building`.

```
my_game/                     a project
  project.godot
  gd++pkg.toml               the package at the project root
  player.gd++                its GD++ code
  .gd++proj/                 downloaded dependencies
  .gd++pkg/                  the package's build cache
  my_game.gdextension        what Godot loads
  libmy_game.linux.debug.x86_64.so
```

# The workflow

```sh
gd++ init . --bind 10.0.0-stable --spec 4.7.2-stable   # make the project root a package
gd++ fetch --missing                                    # download what packages need
gd++ build                                              # build the package you're in
gd++ ls                                                 # see the state of the project
```

Then edit the code and run `gd++ build` again. Open the project in Godot: the classes are there.

# Principles

- Batteries included:
  - Every feature ships in the single `gd++` program.
  - There are no plugins.
  - The only other things to install are the tools that compile C++. `gd++ install` sets them up.
- Minimal friction:
  - A new project takes one or two commands.
  - Source files are found by their extensions. You never list them.
- Moderate configurability, on purpose:
  - Packages choose their dependencies, C++ standard and GD++ syntax.
  - Builds choose their targets and optimization.

# The command line

- All commands share the same global options, output, prompts, errors and paths. See `gd++ man cli` and `gd++ man paths`.
- Each command has its own page under `gd++ man cmd`.
