Enums and constants: enum types, bitfields and constants

`enum` declares two things:

- enum types: sets of named integer values,
- integer constants of a class.

GD++ enum types differ from enums in C++, Godot and GDScript: they're global types of the package.

# Enum types

```gd++
enum Suit {
  DIAMONDS
  CLUBS
  SPADES
  HEARTS
}

enum Rank { JACK = 11, QUEEN, KING, ACE = 1 }
```

- `enum Name { ... }` holds the values: names, each with an optional value after `=`.
- Separate them with spaces, newlines or commas. A trailing comma is fine.
- A value without `=` is the previous value plus one. The first one is 0. So `JACK` is 11, `QUEEN` 12, `KING` 13 and `ACE` 1.
- Bitfields count differently. See "Bitfields" below.
- Values are integers that fit in 64 bits: decimal, negative, hexadecimal, binary or octal, with optional digit separators. See `gd++ man syntax`.
- Two values can't have the same name, but can have the same number.

```gd++
enum Flags {
  NONE = 0
  VISIBLE = 0x1
  SOLID = 0x2
  ALL = 0x3
}
```

A value can be a value of another enum, whose number GD++ copies:

- `Enum.VALUE`, the GD++ spelling: for a GD++ enum or an engine enum.
- `Class.CONSTANT`, the GDScript spelling: for an engine enum of a class.

```gd++
enum MyShadowSetting {
  OFF = GeometryInstance3D.SHADOW_CASTING_SETTING_OFF
  ON = GeometryInstance3D.ShadowCastingSetting.ON
  DOUBLE_SIDED
  HARD = Level.HARD
  ALSO_ON = ON
}
```

GD++ names of engine enum values:

- They leave out the prefix that comes from the enum's name, so that, like GD++ enum values, they have none.
  - `GeometryInstance3D.ShadowCastingSetting`'s `SHADOW_CASTING_SETTING_ON` is `ON`.
  - `Node.ProcessMode`'s `PROCESS_MODE_INHERIT` is `INHERIT`.
- A value keeps its full name if the rest isn't a valid name, e.g. `Key`'s `KEY_3`, or is the name of another value of the enum.
- `Error`'s values keep theirs, e.g. `OK` and `ERR_BUSY`, since they don't start with `ERROR_`.
- Mixing the two spellings is an error, e.g. `GeometryInstance3D.ShadowCastingSetting.SHADOW_CASTING_SETTING_OFF`.
- Global engine enums, e.g. `Error`, only have the GD++ spelling: `Error.OK`.

Values of the enum itself:

- Written with or without the enum's name: `ON` or `MyShadowSetting.ON`.
- Must come before the value that uses them.
- A value without `=` counts on from the value before it, as usual: `DOUBLE_SIDED` is 2.

Values combine with operators, like in C++ and GDScript. From tightest to loosest:

- `~` (bitwise not) and `-` (negation),
- `*` (multiplication), `/` (division) and `%` (remainder),
- `+` (addition) and `-` (subtraction),
- `&` (bitwise and),
- `^` (bitwise xor),
- `|` (bitwise or).

Facts:

- Parentheses group.
- Operators of the same level go from left to right. So `A | B & C` is `A | (B & C)`, and `A - B - C` is `(A - B) - C`.
- They work on 64-bit integers like in GDScript:
  - `~0` is -1.
  - Division rounds toward zero: `-7 / 2` is -3, and `-7 % 2` is -1.
  - Results that don't fit wrap around.
  - Dividing by zero is an error.
- A value ends where no operator continues it. So `A = B | C D` holds two values, `A` and `D`.

```gd++
enum Letter {
  A = 65
  Z = A + 25
  LOWER_A = A | 0x20
  LOWER_Z = Z | 0x20
}

enum Speed {
  SLOW = 10
  FAST = SLOW * 3
  AVERAGE = (SLOW + FAST) / 2
}
```

- In ASCII, setting the bit 0x20 of a capital letter makes it lowercase. So `LOWER_A` is 97, the code of "a".
- For sets of flags, don't write powers of two by hand: use a bitfield. See "Bitfields" below.

Each value can have a doc comment, which Godot's help shows. See `gd++ man docs`.

```gd++
enum Weather {
  /// Clear sky.
  SUNNY
  /// Rain, which makes roads slippery.
  RAINY
}
```

# A global type

A GD++ enum is a type of the whole package: every GD++ file of the package can use it, wherever it's declared. It can be declared:

- at the top level of a file, next to inline classes,
- inside a class, file-level or inline, which changes nothing about its scope,
- as a whole file, with `enum_name`. See `gd++ man files`.

Its name must be unique in the package, like the names of classes, externs, traits and structs.

```gd++
enum_name Suit
DIAMONDS
CLUBS
SPADES
HEARTS
```

# Extending enums

```gd++
enum Suit { DIAMONDS, CLUBS, SPADES, HEARTS }

enum TarotSuit {
  extends Suit
  TRUMPS
}

enum Mode {
  extends Node.ProcessMode
  EDITOR
}
```

`extends Base`, first in the braces, copies all the values of `Base`, with their GD++ names, as if they were written before the enum's own.

- `Base` is a GD++ enum of the package, or an engine enum: one of a class, e.g. `Node.ProcessMode`, or a global one, e.g. `Error`.
- Engine enum values come from the package's API spec. Their GD++ names leave out the enum's prefix, as above. So `Mode` has `INHERIT`, `PAUSABLE`, `WHEN_PAUSED`, `ALWAYS`, `DISABLED` and `EDITOR`.
- Values of a GD++ base keep their names exactly, prefix or not.
- The first own value counts on from the base's last one: `TRUMPS` is 4, and `EDITOR` is 5, after `DISABLED = 4`.
- A bitfield's own flags start above all of its base's values instead. See "Bitfields" below.
- The result is an enum like any other: in C++, a new enum class, e.g. `Mode::INHERIT`, and in Godot, an enum of each class that exposes it, e.g. `Board.MODE_INHERIT`.
- A global enum needs a new name, e.g. `enum KeyCode { extends Key }`, since Godot's names are taken.
- With `enum_name`, `extends` goes on the line after the name:

```gd++
enum_name TarotSuit
extends Suit
TRUMPS
```

# Bitfields

```gd++
@bitfield
enum Layer {
  NONE = 0
  WORLD
  PLAYER
  ENEMY
  ACTORS = PLAYER | ENEMY
}
```

`@bitfield` makes an enum a bitfield: a set of flags, which a value can combine.

- Values without `=` are the flags: powers of two, starting at 1. So `WORLD` is 1, `PLAYER` 2, `ENEMY` 4, and `ACTORS` 6.
- The flags must be next to each other. Values with `=` can come before them, e.g. `NONE`, or after them, e.g. `ACTORS`, but not between them.
- The largest flag is 2^62, so a bitfield has at most 63 flags.
- A bitfield can only extend a bitfield, and an enum only an enum.
- The first own flag of a bitfield that extends another is the smallest power of two above the base's values:

```gd++
@bitfield
enum GameLayer {
  extends Layer
  PICKUP
}

@bitfield
enum MySizeFlags {
  extends Control.SizeFlags
  HUGE
}
```

- `PICKUP` is 8, after `ACTORS = 6`.
- `HUGE` is 16, after `Control.SizeFlags`'s `SIZE_SHRINK_END = 8`.

In C++, a bitfield is an enum class like any other (see "In C++" below), plus:

- the operators `|`, `&`, `^`, `~`, `|=`, `&=` and `^=`, so values combine without casts,
- a value of `&` tests as a `bool`, true if any flag is set. So test a flag with `if (mask & Layer::ENEMY)`.

```gd++
@export var mask: Layer = WORLD | PLAYER

func hits_enemies() -> bool {
  return bool(mask & Layer::ENEMY);
}

func add(layers: Layer = ENEMY) -> void {
  mask |= layers;
}
```

The value of `&`:

- Works as a `bool` where C++ expects a condition: in `if`, `while`, `!`, `&&`, `||` and `? :`.
- Elsewhere, e.g. in `return` or `bool b = ...`, write `bool(...)`.
- Otherwise it's a `Layer`: `Layer hit = mask & Layer::ENEMY;`.
- With `auto`, it stays a `gdpp::Masked<Layer>`, which converts to `Layer` but takes no `|=` and the like. So write the type.

Initial and default values of a bitfield type can combine the bitfield's values with `|`, `&`, `^`, `~` and parentheses, without C++: `WORLD | PLAYER` stands for `Layer::WORLD | Layer::PLAYER`.

In Godot:

- A bitfield is a bitfield of each class that exposes it, like `Control.SizeFlags`.
- In GDScript, its type is e.g. `BitField[Table.Layer]` for a class `Table`, and the help marks it as one.
- An exported variable of a bitfield type shows a checkbox for each value that is a single flag. See `gd++ man exports`.

# In C++

Each enum becomes a C++ enum class with `int64_t` values, in namespace `godot`, in its own header, e.g. `Suit.h`:

```cpp
enum class Suit : int64_t {
  DIAMONDS = 0,
  CLUBS = 1,
  SPADES = 2,
  HEARTS = 3,
};
```

- Values are scoped: write `Suit::HEARTS` in C++ code.
- Convert to and from integers with `as`. See `gd++ man cast`.
- GD++ includes the enum's header wherever it's used.

```gd++
var trump: Suit = Suit::HEARTS

func trump_index() -> int {
  return trump as int64_t;
}

func set_trump_index(i: int) -> void {
  trump = i as Suit;
}
```

Initial and default values of an enum type can name one of the enum's values, without C++:

- `HEARTS` or `Suit.HEARTS` stands for `Suit::HEARTS`.
- For a bitfield, they can also combine them. See "Bitfields" above.
- Anything else is C++, as usual.

```gd++
var trump: Suit = HEARTS

func deal(suit: Suit = Suit.SPADES) -> void { ... }
```

An enum and its base are different C++ types, even with the same values. Convert between them with `as`. Redeclaring an engine enum is how GD++ code uses it as a type:

```gd++
enum ShadowCastingSetting { extends GeometryInstance3D.ShadowCastingSetting }

@export var casting: ShadowCastingSetting = ON

on ready {
  mesh->set_cast_shadows_setting(casting as GeometryInstance3D::ShadowCastingSetting);
}
```

# In Godot

Godot has no global enums for extensions: every enum belongs to a class, e.g. `Node.ProcessMode`. So GD++ gives each class that needs an enum its own copy. A class exposes an enum if:

- it uses the enum in its API: as the type of a variable, a parameter or the return value of a function (except `@override` functions), or a parameter of a signal,
- it imports the enum, with `import Suit`,
- the enum is declared inside it,
- it's a file-level class, and the enum is declared anywhere in its file.

`noimport Suit`:

- stops a class from exposing the enum,
- is an error if the class uses the enum in its API, since Godot must know the enum then.

How a class exposes an enum, bitfields included:

- As integer constants of the class, named after the enum and the value, in UPPER_SNAKE_CASE.
  - `Suit`'s `HEARTS` becomes `SUIT_HEARTS`.
  - `HTTPCode`'s `NOT_FOUND` becomes `HTTP_CODE_NOT_FOUND`.
- They belong to an enum of the class named like the GD++ enum, e.g. `Table.Suit`.
- Two classes that expose the same enum have equal values: `Table.SUIT_HEARTS == Deck.SUIT_HEARTS`.

```gdscript
var s: Table.Suit = Table.SUIT_HEARTS
table.play(Table.SUIT_SPADES)
```

In the editor:

- The help lists the values under the class's constants.
- Variables, parameters and return values of the enum's type show as `int`, with the enum's name.
- An exported variable of an enum type shows a drop-down list of the values.
- A bitfield is marked as a bitfield, and an exported variable shows checkboxes. See "Bitfields" above, and `gd++ man exports`.

# How it's done

- Functions, variables and signals whose types use an enum are bound through a stand-in type per class and enum, named `_gdpp_<Class>_<Enum>`, e.g. `_gdpp_Table_Suit`.
- Godot sees it as the enum `Table.Suit`, or for a bitfield, as the bitfield `Table.Suit`.
- Wrappers named `_gdpp_` followed by the name of the function, getter or setter convert between the stand-in and the real enum.
- Your code never sees them: it uses `Suit`.

See `gd++ man generated`.

# Integer constants

```gd++
class_name Game
extends Node

enum MAX_PLAYERS = 4
enum START_LIVES = 3
```

`enum NAME = VALUE`, inside a class, declares an integer constant of the class.

- In C++: a `static constexpr int64_t` member, e.g. `MAX_PLAYERS` or `This::MAX_PLAYERS`.
- In Godot: an integer constant of the class, e.g. `Game.MAX_PLAYERS` in GDScript.
- Unlike enum types, constants belong to their class: they're only declared inside a class, and share its namespace with functions and variables.
- They take a doc comment, but no annotations.
- GDExtensions can only expose integer constants to Godot. So GD++ only has integer constants, and no `const` keyword.
- For constants of other types, use a `@static` function, or a `static constexpr` member in a `decl` block:

```gd++
@static
func gravity() -> Vector3 {
  return Vector3(0, -9.8, 0);
}

decl {
  static constexpr double PI_2 = 6.28318530718;
}
```

# Rules

- Enum types take only `@bitfield`. Constants take no annotations.
- An integer constant outside a class is an error: "This enum is outside of any class.".
- A value must be an integer, a value of an enum, or those combined with operators. E.g. `A = 1.5` or `A = 1 +` is an error. So is dividing by zero.
- A value of an unknown enum, or an unknown value, is an error. So is an enum that depends on itself through its values.
- A value of an engine enum uses one spelling: `GeometryInstance3D.ShadowCastingSetting.OFF` or `GeometryInstance3D.SHADOW_CASTING_SETTING_OFF`, not `GeometryInstance3D.ShadowCastingSetting.SHADOW_CASTING_SETTING_OFF`.
- An enum can't extend itself through its bases, a class, or an unknown name.
- Its own values can't have the names of inherited ones.
- `extends` comes before the values: `enum A { X extends Suit }` is an error.
- A bitfield's values without `=` must be next to each other. At most 63 flags.
- A bitfield can't extend an enum, and an enum can't extend a bitfield.
- An enum can't be the base of a class, nor an element type of `Array[T]` or `Dictionary[K, V]`. Use `int` there.
