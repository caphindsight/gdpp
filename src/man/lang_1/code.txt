C++ code: function bodies and C++ blocks

Wherever GD++ takes a block in braces, the block is C++: function bodies, `ctor`, `dtor` and `notif` blocks, `get` and `set` blocks, and initial and default values. `decl` and `impl` blocks go further: they put any C++ into the generated files, e.g. private helpers or `#include` lines. This page explains how GD++ treats C++ code, and where each block ends up.

# What GD++ does to C++ code

GD++ copies C++ code into the generated files almost as it is. It only:

- removes comments, keeping their newlines, so line numbers stay the same. Remember that GD++'s block comments nest (see `gd++ man syntax`),
- rewrites a few words of its own: `emit`, `rpc`, `is_cancelled`, `string_name`, `is_done`, `claim`, `cancel`, `create`, `destroy`, `queue_destroy`, `as` and `assert` (see `gd++ man rewrites`),
- wraps it in `#line` directives, so compiler errors point to the line in the GD++ file, not in the generated file.

Everything else is plain C++, compiled by a C++ compiler with the package's C++ standard, against godot-cpp. Code in a class is inside namespace `godot`, like godot-cpp's own code, so Godot's names need no `godot::` prefix.

# This and gd

Two names are available in all C++ code of a class:

This
  The name of the current class, like `Self` in Rust: `This *copy = create This;` or `callable_mp(this, &This::on_hit)`. It's a macro that GD++ defines before the class's code and undefines after it, so it works in function bodies and in `decl` and `impl` blocks, but not in `@global` blocks.

gd
  Short for `UtilityFunctions`, Godot's global functions: `gd::print`, `gd::randf`, `gd::clamp`, `gd::lerp`, `gd::is_instance_valid` and so on. See `gd++ man runtime`.

# decl blocks

```gd++
decl {
  int64_t counter_ = 0;
  void helper();
}
```

A `decl` block goes into the class definition, in the class's header. Its code starts in the private section of the class, so it's for private fields and methods. To make something public or protected, start with an access specifier:

```gd++
decl {
 public:
  void public_helper();      // Public in C++, but unknown to Godot.
 protected:
  void protected_helper();
}
```

Whatever GD++ writes after the block starts its own section, so access specifiers in a `decl` block don't leak.

Functions declared in `decl` blocks are plain C++ methods: Godot doesn't know them, and GDScript can't call them. Define them in an `impl` block, or inline, in the `decl` block itself.

# impl blocks

```gd++
impl {
  void This::helper() {
    counter_++;
  }
}
```

An `impl` block goes into the class's source file, inside namespace `godot`, after the definitions that GD++ generates. It's for the definitions of methods declared in `decl` blocks, and for code that only the source file needs, e.g. static helper functions.

# decl impl blocks

```gd++
decl impl {
  #define MAX_HP 100
}
```

A `decl impl` block goes into both the header and the source file, e.g. for macros that both need. Macros leak into every file that includes the header, so `#undef` them at the end, in another `decl impl` block.

# @global blocks

```gd++
@global decl {
  #include <vector>
  #include <algorithm>
}

@global impl {
  static int instance_count = 0;
}
```

With `@global`, a block goes outside the class and outside namespace `godot`:

- `@global decl`: into the class's header, after the includes, before namespace `godot`.
- `@global impl`: into the class's source file, after the includes, before namespace `godot`.
- `@global decl impl`: into both.

Use them for the `#include` lines of other libraries, e.g. of the C++ standard library, and for declarations at global scope. `This` isn't available in `@global` blocks. The standard library needs no special setup: godot-cpp links it.

`decl` and `impl` blocks must be inside a class, even with `@global`. At the top of a file, before `class_name`, they're an error. The only annotation they take is `@global`, and they take no doc comment.

# Order in the generated files

In the header, for a class:

```
#include lines
@global decl blocks
namespace godot {
class NAME : public BASE {
  GDCLASS(NAME, BASE)
private:     decl blocks, each in turn
public:      fields of simple variables
private:     decl blocks of properties
public:      constants, constructor, destructor, functions, getters, setters, signals
protected:   _bind_methods, _notification
private:     generated helpers
};
}
```

In the source file:

```
#include lines
@global impl blocks
namespace godot {
_bind_methods, constructor, destructor, _notification, functions, getters and setters, signals
impl blocks
}
```

See `gd++ man generated` for all details.

# Includes in C++ code

You don't write `#include` lines for Godot's classes, godot-cpp's names, or the package's GD++ classes, externs and enums: GD++ finds every name that the C++ code uses, and includes its header. See `gd++ man includes`. Write `#include` lines only for other code, e.g. `<vector>`, or the package's plain C++ headers, in `@global` blocks.

# Line numbers

GD++ keeps the line numbers of C++ code: comments are replaced by their newlines, and `#line` directives around each piece of your code tell the compiler where it came from. So when the compiler finds an error in a function body, it names the GD++ file and line:

```
package/player.gd++:12:5: error: 'helth' was not declared in this scope
```

The compiler runs in the package's build cache, so the path is relative to it. Each build compiles copies of the package's files, which it keeps in the build cache's `package/` directory, so errors show the code that was compiled, even if you edit a file during the build. Debuggers use the same information, so they show GD++ files and lines too, in debug builds.

# Examples

A class with a private helper, and a standard container:

```gd++
class_name Pathfinder
extends Node

@global decl {
  #include <queue>
}

decl {
  std::queue<Vector2i> frontier_;
  bool visit(const Vector2i &cell);
}

impl {
  bool This::visit(const Vector2i &cell) {
    if (cell.x < 0 || cell.y < 0) {
      return false;
    }
    frontier_.push(cell);
    return true;
  }
}

func start(from: Vector2i) -> void {
  frontier_ = {};
  visit(from);
}
```
