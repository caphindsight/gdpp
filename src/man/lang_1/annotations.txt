Annotations: the complete list

Annotations attach information to a declaration, like in GDScript: `@export` on a variable, `@override` on a function, `@tool` on a class. This page lists all of them. Each one is explained in full on the page of its topic.

# Syntax

```gd++
@name
@name(ARG, ARG, ...)
```

An annotation is `@` and a name, with arguments in parentheses if it takes any. Arguments are numbers (negative ones too), strings in double quotes, or names. A trailing comma is fine. Annotations go right before the declaration they belong to, on the same line or on the lines before, in any order:

```gd++
@export var speed: float

@export_range(0, 100, 1, "or_greater")
var health: int

@virtual @const
func _score() -> int
```

A declaration's doc comment can come before its annotations or between them, but a declaration has at most one doc comment. See `gd++ man docs`.

# Classes

@tool
  Run the class's code in the editor too. See `gd++ man classes`.

@game_only
  Run the class's code only in the game, never in the editor, not even when other code calls it. Can't be used with `@tool`. See `gd++ man classes`.

@icon(PATH)
  The class's icon in the editor: a string with a `res://` or `pkg://` path. See `gd++ man classes`.

@pool, @pool(SIZE), @pool(SIZE, "strict") and @pool(SIZE, "soft")
  Instead of deleting objects, `destroy` keeps them in a pool, and `create` reuses them. Scripts get `new_pooled()`, or `new_scene_pooled()` with `@scene`, and `free_pooled()` and `queue_free_pooled()` for the same. With SIZE, a positive integer, the pool can hold up to SIZE objects, and `create` returns `nullptr` once all of them are in use, so code must check its result. With `"strict"`, a full pool is also logged as an error. With `"soft"`, the pool has no limit, and in debug builds logs an error when it grows past SIZE objects, and again past each double of that. Only for classes that extend `Node`. See `gd++ man pools`.

@scene(PATH)
  Make `create` instantiate the class's scene: a string with a `res://` or `pkg://` path. The scene is loaded once, and its root must be an object of the class. Scripts get `new_scene()` for the same. Only for classes that extend `Node`. See `gd++ man classes`.

@trace(GROUPS...)
  Trace all its functions (except `_process` and `_physics_process`), variables and signals, and print the creation and destruction of its objects. See "@trace and @profile" below.

@profile(GROUPS...)
  Time all its functions, and the getters and setters of its properties with `get` and `set` blocks. See "@trace and @profile" below.

# ctor and dtor blocks

@recycle
  In a `@pool` class, a `@recycle ctor` runs when the pool reuses an object, and a `@recycle dtor` runs when the pool keeps one. They also run when an object is actually created, after `ctor`, and deleted, before `dtor`, so they run once for each use of an object, unless they have `@recycle("only")`. For `@recycle` on variables, see "Variables of classes" below. The plain `ctor` and `dtor` run only when an object is actually created or deleted. See `gd++ man pools`.

# Functions of classes

@override
@override("final", "super", "engine")
  Override a virtual function of the engine, e.g. `_input`, or a `@virtual` function of a GD++ base class. A script's function of the same name replaces it. The engine functions, `_ready`, `_process` and the like, run from `_notification` without it, and take it only with `"engine"`. Optional arguments, in double quotes: `"final"`, on an override of a GD++ `@virtual` function: subclasses and scripts can't override it any further. `"super"`: also bind the body as `_super_NAME`, which scripts call in place of `super`. `"engine"`, on an engine function: make it a plain override. See `gd++ man functions`.
@virtual
@virtual("private", "super")
  Let subclasses and scripts override the function, whose name must start with `_`, e.g. `_think`. Scripts call it as `think`, which GD++ binds too. Optional arguments, in double quotes: `"private"`: don't bind `think`. `"super"`: also bind the body as `_super_think`, which scripts' overrides call in place of `super`. See `gd++ man functions`.

@const
  Make the function a const method. See `gd++ man functions`.

@static
  Make the function static. See `gd++ man functions`.

@rpc(ARGS...)
  Make the function callable over the network. Arguments: `"authority"` or `"any_peer"`, `"call_remote"` or `"call_local"`, `"unreliable"`, `"unreliable_ordered"` or `"reliable"`, and a channel number, last. Only in classes that extend `Node`. See `gd++ man rpc`.

@deferred
  Every call, from C++ or from Godot, goes through `call_deferred` and runs later. The function must return `void`. See `gd++ man functions`.

@thread_safe
  Like `@deferred`, with `call_thread_safe`: calls from other threads run later, on the main thread. Only in classes that extend `Node`. See `gd++ man functions`.

@onthread
  Every call, from C++ or from Godot, runs the body on the `WorkerThreadPool`, and returns an `Async` of the function's type, through which the caller waits for the body and gets its result. See `gd++ man async`.

@trace(GROUPS...)
  Print each call when it starts, with its arguments, and when it returns, with its result and time. See "@trace and @profile" below.

@profile(GROUPS...)
  Time each call, for the editor's monitors and the profile table. See "@trace and @profile" below.

@notrace and @noprofile
  Leave the function out of its class's `@trace` or `@profile`, and out of the groups `process` and `physics_process`. Its own `@trace` or `@profile` still applies. See "@trace and @profile" below.

@game_only
  Run the function only in the game, never in the editor, e.g. in a `@tool` class. See `gd++ man classes`.

@recycle
  Only on `_ready`, also with `@override("engine")`, in a `@pool` class: run it each time an object gets ready, not only the first time. See "Getting ready again" in `gd++ man pools`.

These can't be combined: `@static` with `@virtual`, `@override`, `@const`, `@rpc`, `@deferred` or `@thread_safe`; `@virtual` with `@override`, `@rpc`, `@deferred`, `@thread_safe` or `@onthread`; `@override` with `@rpc`, `@deferred`, `@thread_safe` or `@onthread`; `@rpc` with `@onthread`; `@deferred` with `@thread_safe` or `@onthread`; `@thread_safe` with `@onthread`. Engine functions only take `@trace`, `@profile`, `@notrace`, `@noprofile` and `@game_only`, and `_ready` also `@recycle`. `@override("final")` only works on an override of a GD++ `@virtual` function. A `@virtual` function's name must start with `_`. `@override` only works on engine functions with `"engine"`, and `"engine"` only works on engine functions.

# Externs

@pool
  The extern's class has `@pool`: `create`, `destroy` and `queue_destroy` use its pool, through its methods for scripts. Takes no arguments: the class configures its pool. Only for externs that extend `Node`. See "Pools and scenes" in `gd++ man externs`.

@scene
  The extern's class has `@scene`: `create` instantiates its scene, through its method for scripts. Takes no arguments: the class names its scene. Only for externs that extend `Node`. See "Pools and scenes" in `gd++ man externs`.

Externs also take `@trace` and `@profile`, which work like a class's on their functions, variables and signals. See "@trace and @profile" below.

# Functions of externs

@const
  The function is a const method of the class.

@deferred
  Call the function with `call_deferred`. The function must return `void`.

@thread_safe
  Call the function with `call_thread_safe`. The function must return `void`. Only in externs that extend `Node`.

@rpc
  The function can be called over the network, with `rpc`. No arguments in externs. Only in externs that extend `Node`.

@trace(GROUPS...)
  Print each call through the extern, like `@trace` on a class's function, marked "extern". See "@trace and @profile" below.

@profile(GROUPS...)
  Time each call through the extern, for the editor's monitors and the profile table, as `extern CLASS.NAME`. Not on `@deferred` and `@thread_safe` functions. See "@trace and @profile" below.

@notrace and @noprofile
  Leave the function out of its extern's `@trace` or `@profile`. See "@trace and @profile" below.

See `gd++ man externs`.

# Variables of classes

@onready
  Assign the initial value right before `_ready`, instead of in the constructor. Only in classes that extend `Node`. In a `@pool` class, only the first time an object gets ready, unless it also has `@recycle`. See `gd++ man lifecycle`.

@recycle
  In a `@pool` class: reset the variable to its initial value, or to its type's default without one, each time the pool reuses an object. With `@onready`: assign the initial value each time an object gets ready, not only the first time. See "Resetting variables" and "Getting ready again" in `gd++ man pools`.

@export
  Show the variable in the inspector, and save it.

@export_range(MIN, MAX[, STEP][, EXTRAS...])
  An `int` or `float` in a range.

@export_enum(NAMES...)
  An `int` or `String` chosen from a list.

@export_flags(NAMES...)
  An `int` of bit flags.

@export_file([FILTERS...])
  A `String` with a file path.

@export_dir
  A `String` with a directory path.

@export_multiline
  A `String` with many lines.

@export_placeholder(TEXT)
  A `String` with a placeholder text.

@export_storage
  Save the variable, but don't show it in the inspector.

@export_category(NAME)
  Start a category of the inspector at this variable.

@export_group(NAME[, PREFIX])
  Start a group of the inspector at this variable.

@export_subgroup(NAME[, PREFIX])
  Start a subgroup of the inspector at this variable.

A variable can have at most one export annotation, and any section annotations. Export and section annotations only work in classes that extend `Node` or `Resource`. See `gd++ man exports`.

# Set blocks of properties

@deferred
  Every call of the setter goes through `call_deferred`, and runs the `set` block later. See "Properties" in `gd++ man variables`.

@thread_safe
  Like `@deferred`, with `call_thread_safe`: calls from other threads run later, on the main thread. Only in classes that extend `Node`. See "Properties" in `gd++ man variables`.

They can't be combined.

@trace(GROUPS...)
  Print each change of its value, with the function of its class that made it. See "@trace and @profile" below.

@profile(GROUPS...)
  Time its getter and setter. See "@trace and @profile" below.

@notrace and @noprofile
  Leave the variable out of its class's `@trace` or `@profile`: its changes aren't printed, or its getter and setter aren't timed. See "@trace and @profile" below.

@game_only
  Run its getter and setter only in the game, never in the editor, e.g. in a `@tool` class. Can't be used with an export annotation. See `gd++ man classes`.

Variables of externs can have `@profile`, which times the calls of their getter and setter through the extern, and `@noprofile`, which leaves them out of the extern's `@profile`.

# Signals

@trace(GROUPS...)
  Print each emission with `emit`, with its arguments. See "@trace and @profile" below.

@notrace
  Leave the signal out of its class's `@trace`: its emissions aren't printed. See "@trace and @profile" below.

Signals of externs can have `@trace` too, which prints each emission through the extern, marked "extern", and `@notrace`.

# Enums

@bitfield
  Make an enum type a bitfield, whose values without `=` are flags: 1, 2, 4, and so on. See `gd++ man enums`.

# Code blocks

@global
  Put a `decl` or `impl` block outside the class and outside namespace `godot`. See `gd++ man code`.

# @trace and @profile

`@trace` and `@profile` are for debugging. They generate code only in builds that turn them on, so they can stay in your code:

```gd++
@trace("combat")
var health: int = 100

@trace("combat", "ai")
@profile
func take_damage(amount: int) -> bool {
  health -= amount;
  return health <= 0;
}
```

```sh
gd++ build --trace combat              # traces health and take_damage
gd++ build --profile Player            # profiles take_damage
gd++ build                             # neither: the annotations generate nothing
```

Their arguments are names of groups, in double quotes: `@trace("combat")` is in the group `combat`. Every annotation is also in the group named after its class, e.g. `Player`, without an argument. The groups `process` and `physics_process` turn on all `_process` and `_physics_process` functions, even without annotations. `gd++ build --trace GROUP...` turns on the `@trace` annotations in those groups, `--profile GROUP...` the `@profile` ones, and `all` turns on all of them. A member is on if its own annotation is on, or its class's, unless it has `@notrace` or `@noprofile`.

`@notrace` and `@noprofile`, on a function or a variable, and `@notrace` on a signal, leave it out of its class's `@trace` or `@profile`, including the groups `process` and `physics_process` for a function. A member's own `@trace` or `@profile` still applies. They need a `@trace` or `@profile` on the class or extern: without one, they're an error. See "Leaving members out" in `gd++ man debugging`.

They combine with every other annotation, and with each other. Externs can have them too, see "Externs" in `gd++ man debugging`. See `gd++ man debugging` for what they print, how to read it, and how to use them well.

# No annotations

Enum values, integer constants, `ctor`, `dtor`, `notif`, `import` and `noimport` take no annotations. Externs themselves only take `@pool`, `@scene`, `@trace` and `@profile`, see "Externs" above.

# Errors

- An unknown annotation is an error, with a suggestion if it looks like a typo: "Unknown annotation @exprot." with "Did you mean \"@export\"?".
- An annotation in the wrong place is an error, e.g. "Annotation @tool can't be used on a func.".
- An annotation can be used once per declaration: "Annotation @export is used twice.".
- Annotations that take no arguments reject them: "Annotation @const takes no arguments.".
- `@trace` and `@profile` take only names in double quotes: "Annotation @trace takes names of groups in double quotes, e.g. @trace("combat").".
- Some annotations need a base class: "Annotation @onready can only be used in classes that extend Node, which Item doesn't.".
- An annotation that isn't followed by a declaration is an error: "Expected a declaration after the annotation, ...".

# Not in GD++

Some GDScript annotations have no GD++ version, since GD++ does the same another way, or it doesn't apply to C++:

- `@abstract`, `@static_unload`, `@warning_ignore` and the like: not supported.
- `@export_node_path`, `@export_color_no_alpha`, `@export_exp_easing`, `@export_global_file`, `@export_global_dir` and the like: not supported yet. Use `@export`, or a property of the right type.
- `static`, `const` and `onready` without `@` are not keywords: write `@static` and `@onready`, and `enum NAME = VALUE` for constants.
