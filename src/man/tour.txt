Tour: a first project

This page walks through a small project. Each step links to the pages that explain it in full.

# 1. Install the tools

Build and install `gd++` from source:

```sh
make && sudo make install
```

Install the tools that compile C++ (Git, SCons, Python and a C++ compiler):

```sh
gd++ install
```

- It asks before running anything.
- `gd++ install --echo` shows its commands without running them.

See `gd++ man install`.

# 2. Make a Godot project

- Create a project in the Godot editor, as usual. Any Godot 4 project works, i.e. a directory with a `project.godot` file.
- Open a terminal in the project directory.
- Every `gd++` command finds the project from the current directory, like git finds its repository. So any subdirectory works too.

# 3. Create a package

A package is a directory whose code builds into one GDExtension library. For a small game, one package at the project root is enough:

```sh
gd++ init . --bind 10.0.0-stable --spec 4.7.2-stable
```

This writes `.gd++pkg.toml`:

```toml
bind = "10.0.0-stable"
spec = "4.7.2-stable"
syntax = 1
std = "c++20"
```

- `bind`: the Godot C++ bindings to build with.
- `spec`: the Godot API spec, i.e. the Godot version to target. It must not be newer than the Godot that runs the game.
- `gd++ fetch --index` lists the versions that exist.
- With git, also run `gd++ init --vcs git`. It adds GD++'s files to `.gitignore`. See `gd++ man vcs`.

See `gd++ man packages` and `gd++ man init`.

# 4. Download the dependencies

```sh
gd++ fetch --missing
```

This downloads the bindings and the spec that your packages name, into the project's `.gd++proj` directory. See `gd++ man dependencies` and `gd++ man fetch`.

# 5. Write a class

Save this as `player.gd++`, anywhere in the package:

```gd++
class_name Player
extends CharacterBody2D

/// How fast the player runs, in pixels per second.
@export_range(0, 1000, 1)
var speed: float = 300.0

signal jumped

on physics_process(delta: float) {
  Vector2 direction = Input::get_singleton()->get_vector(string_name "ui_left", string_name "ui_right", string_name "ui_up", string_name "ui_down");
  set_velocity(direction * speed);
  move_and_slide();
  if (Input::get_singleton()->is_action_just_pressed(string_name "ui_accept")) {
    emit jumped();
  }
}
```

- The top lines are GD++: a class, a property shown in the inspector, and a signal.
- `on physics_process` runs every physics frame. Its body is C++.
- `emit` sends the signal. It's a GD++ rewrite.
- You didn't write a header, `#include` lines, `_bind_methods`, a getter and setter for `speed`, or class registration.

See `gd++ man lang`.

# 6. Build

```sh
gd++ build
```

- The first build is slow: it compiles godot-cpp.
- Later builds only compile what changed.
- The build writes the library, e.g. `libmy_game.linux.debug.x86_64.so`, and `my_game.gdextension` into the package root. Godot loads them right away.

See `gd++ man building` and `gd++ man build`.

# 7. Use the class in Godot

- Open the project in the Godot editor.
- `Player` is now a node type: add it to a scene, set its speed in the inspector, and run the game.
- Its doc comment shows up in the editor's help.
- Debug builds support hot reload: change the code, run `gd++ build`, and the editor picks up the changes when its window gets focus.

# 8. Look under the hood

```sh
gd++ trans player.gd++
```

This prints the C++ that GD++ generates: `Player.h` and `Player.cpp`. See `gd++ man trans` and `gd++ man generated`.

```sh
gd++ ls
```

This shows the project's dependencies, packages and classes. See `gd++ man ls`.

# 9. Ship

Build in release mode, for each target platform:

```sh
gd++ build --ship --for l.x64 w.x64
```

Then export the game from Godot's Export dialog, as usual. See `gd++ man shipping`.

# Where to go next

- `gd++ man tut`: tutorials for common goals, e.g. porting GDScript, shipping or debugging.
- `gd++ man lang`, then the other language pages: GD++ in depth.
- `gd++ man cli`: the options that every command takes.
- `gd++ man debugging`: tracing and profiling with `@trace` and `@profile`.
- `gd++ man`: the list of all pages.
