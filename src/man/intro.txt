Introduction: what GD++ is

# What GD++ is

GD++ lets you write Godot games in C++ without the boilerplate. It is one command line program, `gd++`, with two jobs:

- A small build system for Godot C++ code:
  - It downloads the Godot C++ bindings (godot-cpp) and the Godot API specs.
  - It keeps them in your project.
  - It compiles your code into GDExtension libraries, which Godot loads like its own modules.
- The compiler of the GD++ language:
  - GD++ compiles to plain C++.
  - Declarations look like GDScript.
  - Function bodies are C++, with a few rewrites. See `gd++ man rewrites`.
  - GD++ writes the glue code that Godot needs: headers, `_bind_methods`, getters and setters, `#include` lines and class registration.

Speed, in release builds:

- Your own logic, like math and loops, runs 15 to 50 times faster than in GDScript.
- Code that mostly uses Godot's types, like `Array` and `Dictionary`, or calls the engine, gains much less.

See `gd++ man performance`.

A GD++ class, saved as `hello_world.gd++` anywhere in a Godot project:

```gd++
class_name HelloWorld
extends Node

on ready {
  Label *label = create Label;
  label->set_text("Hello, world!");
  add_child(label);
}
```

Three commands, run in the project directory, turn it into a node type that Godot knows:

```sh
gd++ init . --bind 10.0.0-stable --spec 4.7.2-stable
gd++ fetch --missing
gd++ build
```

Design goals:

- All in one, like Godot: every feature ships in one tool.
- A joy to use: a new project takes one or two commands to set up.
- A little configurable, on purpose not more: more options would make it harder to use.

# What you need

- Godot 4, to run your game.
- `gd++` itself, written in Go. To build it from source, run `make && sudo make install`. This copies the `gd++` binary to `/usr/local/bin`.
- The tools that compile C++: Git, SCons, Python and a C++ compiler. `gd++ install` installs them with your system's package manager. See `gd++ man install`.

You don't download godot-cpp or anything else from Godot yourself: GD++ does it.

# How to read this manual

- `gd++ man` lists all pages, in reading order.
- `gd++ man PAGE` shows one page, e.g. `gd++ man classes`.

Pages that don't fit the terminal open in a pager:

- Up and down scroll by a line.
- Page up and page down, or space, scroll by a page.
- q, escape or Ctrl+C quit.
- `/` searches: type the text and press Enter. Matches are highlighted, ignoring case.
- n and Shift+N jump to the next and the previous match.
- q ends the search, so it takes a second q to quit.

When the output is not a terminal, e.g. in `gd++ man classes > classes.txt`, pages are printed as they are.

The manual is a tree of pages. At its top are this page, `tour` (a first project), and four sections:

- `tut`: tutorials, one page per goal, e.g. shipping a game.
- `tool`: the build tool, i.e. projects, packages, dependencies and builds.
- `cmd`: one page per `gd++` command, with all its options.
- `lang`: the GD++ language, one page per topic.

Facts about pages:

- A section's page gives an overview, and ends with the list of its pages.
- Every page has a unique name and a path: `gd++ man functions` and `gd++ man lang/functions` show the same page.
- Pages refer to each other by name, e.g. "see `gd++ man externs`".
- In examples, lines like `gd++ build` are shell commands.
- Code examples are GD++, unless the page says otherwise.
- The tutorials and the language pages describe one syntax version: in a package, the package's, and elsewhere the latest stable one. `gd++ man --syntax N PAGE` shows another version's page. See `gd++ man man`.

# Where else to look

- `gd++ --help` and `gd++ COMMAND --help`: the options of each command, in short.
- `gd++ trans FILE`: the C++ that GD++ generates from a file. The best way to learn what the language does. See `gd++ man trans`.
- `gd++ doc NAME`: what godot-cpp or the GD++ runtime declares under a name, e.g. a class and its methods. See `gd++ man doc`.
- Godot's help, in the editor: the engine's classes, and your GD++ classes with their doc comments. See `gd++ man docs`.

# Glossary

- Project: a Godot project, i.e. a directory with a `project.godot` file. See `gd++ man projects`.
- Package: a directory in a project with a `gd++pkg.toml` file. It builds into one GDExtension library. See `gd++ man packages`.
- Dependency: a versioned download that packages need: Godot C++ bindings, a Godot API spec or a Godot engine. See `gd++ man dependencies`.
- Bindings: godot-cpp, the C++ library that GDExtensions are written against.
- API spec: `extension_api.json`, the description of every class of one Godot version.
- GD++ file: a file with the extension `.gd++`, `.gdpp` or `.gg`.
- Build cache: a package's `.gd++pkg` directory, where builds happen. See `gd++ man build-cache`.
- Transpile: turn GD++ code into C++ code.
- Rewrite: one of GD++'s few additions to C++ code, e.g. `emit` or `as`, which GD++ turns into plain C++. See `gd++ man rewrites`.
