Projects: what GD++ adds to a Godot project

A GD++ project is just a Godot project, i.e. a directory with a `project.godot` file. There is nothing to convert. This page lists what GD++ adds to it.

# What GD++ reads from project.godot

From the `[application]` section, which Godot writes:

- `config/name`: the project's name, shown by `gd++ ls`.
- `config/features`: the Godot version the project was made with, e.g. `4.3`, shown by `gd++ ls`.

Facts:

- If either is missing, commands fail with "Failed to find the project name in res://project.godot." or "Failed to find the Godot version in ...". Open the project in the Godot editor once to fix it.
- `gd++` never writes `project.godot`.
- With `[names]` in a package's `.gd++pkg`, GD++ also reads the input actions, global groups and layer names. See `gd++ man project-names`.
- The project's id is the name of its root directory. The package at the project root has the same id.

# .gd++proj

`res://.gd++proj` holds the project's GD++ settings.

- It's a TOML file. It has no `.toml` extension, so the Godot editor doesn't show it.
- It's optional: without it, every setting has its default.
- `gd++ init` without a path creates it.
- Unknown keys are an error: "Unknown key ... in res://.gd++proj.".
- `gd++ fix` reformats it to its canonical form.

```toml
vcs = "none"
presets = true
```

vcs
  The version control system: `"none"` (the default) or `"git"`. With `"git"`, GD++ keeps its blocks of ignores in the `.gitignore` files of the project and its packages. See `gd++ man vcs`.

presets
  Whether GD++ keeps its sources and config files out of exported games: `true` (the default) or `false`.
  - `true`: `gd++ build` and `gd++ fix` add GD++'s exclude filters to every preset in `res://export_presets.cfg`.
  - `false`: they remove them once, and then leave the file alone.
  - Set it with `gd++ init --presets` or `--nopresets`. See `gd++ man shipping`.

# What GD++ adds to a project

```
res://
  project.godot        Godot's, never changed by GD++
  export_presets.cfg   Godot's, GD++ adds its exclude filters to every preset
  .gd++proj            the project's GD++ settings (optional)
  .gd++cache/          the ephemeral dependency cache
    bind/NAME/         Godot C++ bindings
    spec/NAME/         Godot API specs
    engine/NAME/       Godot engines
    temp/              temporary files of running commands
  _gd++/               the checked in dependency cache
    bind/NAME/  spec/NAME/  engine/NAME/
  some_package/        a package (any directory with a .gd++pkg)
    .gd++pkg
    .gd++build/        the package's build cache
    some_package.gdextension, .gdextension.uid, lib*.so/.dll/.dylib
```

- Dependency caches: see `gd++ man dependencies`.
- Packages: see `gd++ man packages`.
- Build caches: see `gd++ man build-cache`.

Facts:

- `gd++` creates directories only when it first needs them. A fresh project has none of them.
- It deletes cache directories that become empty, e.g. after you remove the last dependency.
- When it creates `res://_gd++`, `res://.gd++cache` or a package's `.gd++build`, it writes an empty `.gdignore` file into it. So Godot never imports the files in the caches.
- Commit `res://_gd++/.gdignore` with the rest of `res://_gd++`.

# Temporary files

- `gd++ fetch` and `gd++ vendor` work in a randomly named directory in `res://.gd++cache/temp`.
- They delete it when they finish or fail.
- If `gd++` is killed, e.g. with Ctrl+C, the directory may stay behind. `gd++ fix` deletes it.

# Many packages in one project

- A project has any number of packages, anywhere in it, including at its root and nested in each other.
- Each one builds into its own library.
- `gd++ build res://...` and `gd++ clean res://...` work on all of them. `DIR/...` means every package in `DIR`.
- `gd++ ls` shows them all.
- Packages share the dependency caches, but each one chooses its own bindings and spec.

# Nested projects

A directory inside a project with its own `project.godot` file is a separate project.

- Commands on the outer project don't look inside it.
- Commands run inside it work on it, not on the outer project.

# Example

A project with two packages:

```
my_game/
  project.godot
  .gd++proj            vcs = "git", presets = true
  .gitignore
  gameplay/
    .gd++pkg
    player.gd++
    enemy.gd++
  tools/
    .gd++pkg
    level_editor.gd++
```

Set up with:

```sh
cd my_game
gd++ init --vcs git                                              # creates .gd++proj
gd++ init gameplay --bind 10.0.0-stable --spec 4.7.2-stable
gd++ init tools --bind 10.0.0-stable --spec 4.7.2-stable
gd++ fetch --missing
gd++ build res://...
```
