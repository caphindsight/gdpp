The command line: what all commands share

`gd++` is one program with many commands, like git: `gd++ COMMAND [OPTIONS] [ARGUMENTS]`. This page covers what all commands share: global options, output, prompts and errors.

# Commands

```
gd++ build     compile a package into a GDExtension library
gd++ cat       show files in the pager, highlighting C++ and GD++ code
gd++ checkin   check in dependencies from the ephemeral cache, or undo it
gd++ clean     delete the build caches of packages
gd++ doc       show the declaration and members of a godot-cpp class or function
gd++ fetch     download dependencies from a repository, or list them
gd++ fix       tidy up the project, e.g. delete leftover temporary files
gd++ init      set up the project, or create or update a package
gd++ install   install the tools GD++ needs to build, e.g. SCons and a C++ compiler
gd++ ls        show an overview of the project, its dependencies and packages
gd++ man       read the reference manual of GD++ and its language, or list its pages
gd++ rm        remove dependencies from the project cache, or packages from the project
gd++ trans     transpile a GD++ file and print the C++ it generates
gd++ vendor    copy a dependency into or out of the project's cache
```

- Each command has its own manual page, e.g. `gd++ man build`.
- `gd++ --help` lists the commands.
- `gd++ COMMAND --help` lists the options of one command.
- `gd++` without a command is an error: "Missing subcommand, see `gd++ --help`."

# Global options

These work with every command, before or after its name: `gd++ -v build` and `gd++ build -v` are the same.

-q, --quiet
  Print fewer logs. Hides info messages, warnings and subprocess output. Errors and command results are always printed.

-v, --verbose
  Print more logs: also steps that are normally quiet, e.g. "Syncing dependencies..." during a build, and subprocess output that is normally hidden, e.g. git's. Not with `-q`.

-f, --yes
  Answer yes to every confirmation prompt. Needed to confirm anything when the output is not a terminal, e.g. in scripts. Not with `-n` or `--audit`.

-n, --no
  Answer no to every confirmation prompt. The command stops at the first prompt, with "Operation canceled by -n/--no." Shows what a command would ask, without risk. Not with `-f`.

--audit
  Ask before potentially dangerous operations that normally run without asking. Currently: deleting a directory that isn't empty. Not with `-f`.

--tty
  Act as if the output were a terminal: colors, icons, spinners, the pager and prompts, even when the output is redirected. Not with `--notty`.

--notty
  Act as if the output were not a terminal: plain text, no styles, spinners or pager, and prompts assume no. Not with `--tty`.

--pager
  Show long results, e.g. of `gd++ man` and `gd++ cat`, in the pager even when they fit the terminal. No effect when the output is not a terminal. Not with `--notty`.

-L N, --log-depth N
  Show the last N lines of a running subprocess's output under its task, e.g. the compiler's. Default: 4.

-T N, --tab-width N
  Tab width, in columns, in the pager (e.g. in `gd++ cat` and `gd++ trans`) and in the images of `gd++ cat --svg`. Also the indent of `gd++ doc`'s output, in spaces. At least 1. Default: 2.

--version
  Print the version of GD++, e.g. "nightly", and exit. Not with a command.

--syntax
  Print the GD++ syntax versions that this `gd++` supports, marking the nightly and the latest stable one, and exit. Not with other arguments. Commands that take `--syntax N`, e.g. `gd++ init`, use it to choose a version instead. See "Syntax versions" in `gd++ man packages`.

-h, --help
  Print help and exit.

List options, e.g. `gd++ fetch --bind A B` or `gd++ build --for l.x64 w.x64`:

- They take all the values that follow, up to the next option.
- If repeated, only the last values count: `--for l.x64 --for w.x64` builds for `w.x64` only.

# Output

- Results go to standard output (stdout), e.g. the overview of `gd++ ls`, the C++ of `gd++ trans` or a page of `gd++ man`. So you can redirect them: `gd++ trans player.gd++ > player.txt`.
- Logs, progress and prompts go to standard error (stderr).

Log messages start with an icon:

```out
[•] An info message, e.g. "Success!"
[!] A warning: something to know, which didn't stop the command.
[×] An error. The command stops.
[?] A question, answered with y or n.
```

Without a terminal, or on a terminal that can't show them (e.g. the Linux text console or the old Windows console), the icons are "-", "!", "x" and "?".

- A command that changed something ends with "Success!".
- A command with nothing to do says so, e.g. "Nothing to clean." or "No changes were made.".

Tasks are long running steps, e.g. compiling:

- On a terminal, a task shows a spinner with its name, and under it the last lines of its subprocess's output (see `-L`).
- When the task ends, these lines disappear and the spinner becomes an info icon.
- When the task fails, its whole output is printed. After a long output, the task's name is repeated.

Styles:

- Colors and icons are used only when both stdout and stderr are terminals.
- Otherwise, all output is plain text, with no styles, spinners or pager. Each task prints "Running task: ...", its output lines indented, and "Task succeeded: ..." or "Task failed: ...".
- `--tty` and `--notty` override this.

Paths in messages:

- Inside the project, they are `res://` paths, e.g. `res://src/player.gd++`.
- Elsewhere, they are relative to the current directory.
- `gd++` never prints your absolute paths, so logs are safe to share.

The pager:

- Used by `gd++ cat`, `gd++ doc`, `gd++ man` and `gd++ trans`, when the result doesn't fit the terminal, or always with `--pager`.
- Up and down scroll by a line. Page up and page down, or space, scroll by a page.
- q, escape or Ctrl+C quit.
- `/` searches: type the text and press Enter. Matches are highlighted, ignoring case.
- n and Shift+N jump to the next and the previous match.
- q ends the search, so it takes a second q to quit.

# Prompts

Before a command does something that can't be undone, e.g. deleting a dependency or overwriting a file, it asks:

```out
[?] Remove the Godot API spec 4.3-stable? [y/n]
```

- y or yes goes on. n or no stops. Anything else asks again.
- A command asks all its questions before it changes anything. So answering no leaves everything as it was.
- Without a terminal, `gd++` assumes no and stops with "Output is not a tty, use -f to confirm.".
- In scripts, pass `-f`/`--yes` to confirm everything, or `-n`/`--no` to refuse everything.

# Errors

A failing command prints an error and exits with status 1. Errors say what went wrong, and usually how to fix it:

```out
[×] Missing Godot C++ bindings 10.0.0-stable, run `gd++ fetch --missing` to fix this.
```

- "Invalid arguments: ..." means the options don't make sense together. `gd++` checks the arguments before it changes anything.
- If `gd++` fails halfway, e.g. on an interrupted download, it deletes its temporary files before exiting.

Errors in GD++ code show the file, line and column, the line with a caret under the problem, and a hint:

```out
[×] res://src/player.gd++:4:13: Unknown type "Vectr3".
     4 | var target: Vectr3
       |             ^^^^^^
    Hint: Did you mean "Vector3"?
```

See `gd++ man errors`.

# Exit status

- 0: success, including when a command had nothing to do.
- 1: any error, or a prompt answered no.

# Where commands run

- Most commands work on the project that contains the current directory. `gd++` looks for a `project.godot` file in the current directory, then in its parent, and so on. So any subdirectory of a project works.
- Commands that work on one package, e.g. `gd++ build`, find the package that contains the current directory, or the path you pass, the same way.

See `gd++ man paths`.
