Syntax: tokens, comments and literals

This page covers the lexical structure of GD++: tokens, comments, literals and scopes. For the grammar of declarations, see `gd++ man grammar`.

# Files

- A GD++ file is a UTF-8 text file with the extension `.gd++`, `.gdpp` or `.gg`.
- Line endings can be `\n` or `\r\n`.
- GD++ is not whitespace sensitive, unlike GDScript. Indentation and spacing don't matter, except where this page says so.

# Scopes

A file has five kinds of scope:

1. The class declaration scope.
   - Where: the top of a file, the rest of a file after `class_name`, `extern_name` or `trait_name`, and the inside of `class Name { ... }`, `extern Name { ... }` and `trait Name { ... }`.
   - Holds: `func`, `shader`, `var`, `signal`, `enum`, `ctor`, `dtor`, `on`, `decl`, `impl`, shader blocks, `import` and `noimport`, and at the top level, classes, externs and traits.
   - The syntax looks like GDScript, but it's GD++'s own. See `gd++ man files`.
2. The property declaration scope.
   - Where: the braces after `var name: type { ... }`.
   - Holds: only `decl`, `get` and `set` blocks. See `gd++ man variables`.
3. The enum declaration scope.
   - Where: the braces after `enum Name { ... }`, and the rest of a file after `enum_name`.
   - Holds: an optional `extends`, then the enum's values. See `gd++ man enums`.
4. The C++ scope.
   - Where: every other pair of braces, i.e. function bodies, `ctor`, `dtor` and `on` blocks, `decl` and `impl` blocks, `get` and `set` blocks, and initial and default values.
   - Holds: any C++ code, which GD++ copies into the generated C++. See `gd++ man code`.
5. The GLSL scope.
   - Where: the bodies of shaders, shader blocks, and the rest of a file after `shader_library`.
   - Holds: GLSL code, which runs on the GPU. See `gd++ man shaders`.

All scopes share the same tokens, described below, and the same comments. So a C++ block ends at the `}` that matches its `{`. Braces inside strings, character literals and comments don't count.

# Comments

```gd++
// A line comment, to the end of the line.
/* A block comment. */
/* Block comments /* nest */, so this is still a comment. */
```

- Block comments nest, like in Rust but unlike in C++: every `/*` inside a block comment needs its own `*/`.
- This holds in C++ code too. So this common C++ trick doesn't work:

```gd++
/* Disabled: /* old code */     <- still inside the comment here
```

- Comments are removed from the generated C++.
- A comment is replaced by the newlines it spans, or by a space if it spans none. So the lines of the generated code still match the lines of the GD++ file.

# Doc comments

```gd++
/// A doc comment: three slashes.
/// More lines continue it.

/**
  A block doc comment: a slash and two stars.
*/
```

- A doc comment documents the declaration right after it, and becomes Godot's help for it. See `gd++ man docs`.
- A doc comment not followed by a declaration is an error.
- In C++ code, doc comments are plain comments.
- These look-alikes are plain comments:

```gd++
////    four or more slashes
/**/    an empty block comment
/***    three or more stars
```

# Identifiers

- Made of letters, digits and underscores, not starting with a digit: `[A-Za-z_][A-Za-z0-9_]*`.
- They name classes, functions, variables, types and so on.
- Case sensitive.
- Only ASCII letters.

# Keywords

Keywords have a special meaning in declarations. Don't use them as names of classes, functions, variables and the like, since GD++ would misread them:

```gd++
annotation  class  class_name  ctor  decl  dtor  enum  enum_name  extends  extern
extern_name  func  get  impl  implements  import  invoke  macro  macro_library  macro_name  noimport
on  set  shader  shader_library  signal  template  template_name  trait  trait_name  var
```

- `code` is a keyword only right before `{`, in a macro's arguments. See `gd++ man macros`.
- GD++ has no other keywords. E.g. `const`, `static`, `pass`, `if` and `return` are not GD++ keywords.
- Attributes such as `@static` are annotations. Your own annotations start with `@@`, e.g. `@@save`. See `gd++ man annotations`.

In C++ code, GD++ reserves seventeen more names:

- the rewrites `emit`, `rpc`, `is_cancelled`, `string_name`, `is_done`, `claim`, `cancel`, `create`, `destroy`, `queue_destroy`, `as` and `assert`, with its fallbacks `assert_void` and `assert_val`. See `gd++ man rewrites`.
- `This` and `gd`. See `gd++ man code`.
- `invoke`, which invokes macros, e.g. `invoke log("hit");`. See `gd++ man macros`. Templates don't work in C++ code.
  `invoke { ... }` is a macro block, which runs its Lua code right there, e.g. `invoke { gd.text("x++;") }`.

# Numbers

Numbers are written like in C.

- Declarations use integers in enum values and constants.
- Annotation arguments take integers or floating point numbers, e.g. `@export_range(0.0, 1.5, 0.01)`.
- Integers must fit in a signed 64-bit integer.
- In C++ code, any C++ number works, e.g. `1.5e-3`, `0x1p4`, `10u` or `1'000.0f`.

Integer forms:

```gd++
42        decimal
-7        negative
0x2A      hexadecimal
0b101010  binary
052       octal, with a leading 0
1'000'000 with C++14 digit separators
```

# Strings and characters

```gd++
"A string, with \"escapes\"."
'c'                           a character
u8"UTF-8", u"UTF-16", U"UTF-32", L"wide"
R"(A raw string, with "quotes" and } braces.)"
R"delim(A raw string ending with )delim"
```

- Strings end on the same line.
- Raw strings, like in C++, can span lines. They end with `)`, their delimiter, and a quote.
- In declarations, strings are only annotation arguments, in double quotes.
- In C++ code, strings keep their C++ meaning.
- An apostrophe not closed on the same line is not a character literal. So C++ code like `#error don't` works.

# Punctuation

- The arrow `->` is one token.
- Every other punctuation character is a token of its own: `(`, `)`, `[`, `]`, `{`, `}`, `,`, `:`, `=`, `@`, `-` and so on.
- In C++ code, all of C++'s operators work.

# Brackets

- Every `(`, `[` and `{` in the file must be closed by the matching `)`, `]` or `}`, in C++ code too.
- GD++ checks this first, for the whole file. It reports the bracket that is never closed, or the one that doesn't match.
- A missing `}` usually shows up as a `}` indented differently from its `{`. GD++ uses that to point at the right place.

# Values after "="

After the `=` of a variable's initial value, or of a parameter's default value, comes C++ in one of two forms:

- An expression, up to the end of the line.
  - It continues on the next lines while a bracket is open.
  - A default value also ends at a `,` outside brackets, and at the `)` of the parameter list.
- A block in braces, which returns the value, like a function body.

```gd++
var a: int = 1 + 2
var b: int = compute(1,
  2)
var c: Array = {
  Array res;
  res.push_back(1);
  return res;
}
```

See `gd++ man variables` and `gd++ man functions`.
