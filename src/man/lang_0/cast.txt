Cast: converting values with as

C++ and godot-cpp have many ways to convert a value: `static_cast`, `Object::cast_to`, `Ref`'s constructors and `VariantCaster`. GD++ code needs one: `VALUE as T` converts VALUE to the C++ type T, whatever the two types are, like GDScript's `as`.

```gd++
func spawn(scene: PackedScene, mode: ProcessMode) -> Node3D {
  Gd<Node3D> node = scene->instantiate() as Gd<Node3D>;
  node->set_process_mode(mode as Node::ProcessMode);
  return node;
}
```

`as` is a rewrite: GD++ turns `VALUE as T` into `gdpp::cast<T>(VALUE)`, a function of the runtime header. See `gd++ man rewrites`.

# Precedence

- `as` binds VALUE like member accesses and calls do, tighter than any other operator.
  - `a + b as float` converts `b` only.
  - `-x as int` is the negation of `x as int`.
  - Use parentheses to convert more: `(a + b) as float`.
- T ends before anything that isn't part of a type.
  - `n as int < limit` compares.
  - `x as Gd<Mesh>` names a template.
  - A `*` after T is part of it, e.g. in `x as Node3D *`. Write `(x as int) * y` to multiply.
- VALUE must be a name or an expression in parentheses, followed by any member accesses, scopes, calls and subscripts, e.g. `body`, `this->items[i]`, `get_node("Mesh")` or `(a + b)`.
- GD++ only rewrites `as` where VALUE and T are clear. Elsewhere, e.g. in `x as int * y` or `(int) x as float`, the `as` stays, and the C++ doesn't compile. Parentheses fix it: `(x as int) * y`, `((int) x) as float`.

# What it does

`as` picks the conversion at compile time, from the two types. Nothing is decided while the game runs.

```
FROM                    TO                       CONVERSION
the same type           T                        none: the value itself
Variant                 any type                 as Godot's bindings do, an enum from an int
any type                Variant                  as Godot's bindings do, an enum as an int
an object               its class, or a base     static: free
an object               another class            dynamic: checks the object's class, null if it doesn't match
an object               a trait                  static if its class implements it, else checked: null if it doesn't
anything else           T                        static_cast, e.g. numbers, enums, Array to Array[T]
```

- An object is a `Gd` of a class, an extern or a trait (see `gd++ man gd`), an `Async`, or a `Weak`.
- Any of them converts to any other that fits: a class to an extern, an extern to its base class, a `Gd<RefCounted>` to an `Async`, and so on.
- godot-cpp's plain pointers (e.g. `Node3D *`) and `Ref`s (e.g. `Ref<Mesh>`) are objects too, both as values and as targets, e.g. `node as Node3D *`. Prefer `Gd`.
- A conversion that no row allows, e.g. from a `String` to a `Gd<Node3D>`, doesn't compile.

# Upcasts and downcasts

- Upcast: to the object's own class, or to a class it extends.
  - It always works, so `as` does it statically, at no cost.
- Downcast: to a class that extends it, or to an unrelated class.
  - It only works if the object is of that class.
  - `as` checks the class while the game runs, like `Object::cast_to`.
  - Like GDScript's `as`, it gives null if it doesn't match. So check the result.
  - A downcast of a null object gives null.
- `as` keeps `const`: a `Gd<const Node>` casts to a `Gd<const Node3D>`, but not to a `Gd<Node3D>`.

```gd++
func _on_body_entered(body: Node3D) -> void {
  if (auto player = body as Gd<Player>) {
    player->hurt(10);
  }
}
```

# Enums

An enum converts to and from `int`, and to and from another enum, e.g. a GD++ enum to the engine enum it extends:

```gd++
enum ShadowCastingSetting { extends GeometryInstance3D.ShadowCastingSetting }

@export var casting: ShadowCastingSetting = ON

on ready {
  mesh->set_cast_shadows_setting(casting as GeometryInstance3D::ShadowCastingSetting);
  gd::print(casting as int64_t);
}
```

# Variants

- A `Variant` converts to any type, the way Godot converts the arguments of a bound method: to an enum from an `int`, to a `Gd` or an `Async` from an object, and so on.
- A value of the wrong type converts like in a bound method, e.g. to null for objects, and to 0 for numbers.
- Any type converts to a `Variant`. An enum converts as its `int`.

```gd++
func take(task: Variant) -> void {
  Async<int64_t> pending = task as Async<int64_t>;
  ...
}
```

# Externs and Async

An extern casts like an object of its base class:

- like a `Gd<Node>` for an extern `Road` that extends `Node`,
- like a `Gd<Resource>` for an extern `Settings` that extends `Resource`.

```
FROM                    TO                       CONVERSION
Gd<Object>              Gd<Road>                 checked: null if it isn't a Node
Gd<Road>                Gd<Node>                 static: free
Gd<Road>                Gd<Node3D>               checked downcast, null if it doesn't match
Gd<Resource>            Gd<Settings>             static: free, since Settings extends Resource
Gd<Settings>            Gd<Resource>             static: free
Variant                 Gd<Road>                 as Godot's bindings do
```

```gd++
Gd<Terrain> terrain = get_node("Terrain") as Gd<Terrain>;
```

Facts:

- The check stops at the base class. Godot can't cheaply check a script class, so a `Node` with another script still converts to `Road`.
- For the same reason, a cast between two externs with the same base class isn't checked at all.
- An `Async` converts from any refcounted object, which should be a task object of some package, and to a `Gd<RefCounted>`.

See `gd++ man externs` and `gd++ man async`.

# Traits

A trait is spelled `Gd<T>` in C++, e.g. `body as Gd<Damageable>`:

- A cast to a trait checks the object's class, unless the class is known to implement it. It gives null if the class doesn't.
- A trait value casts like an object of the trait's base class: free to the base, checked to any other class.
- The check knows the package's classes only. An object with a script counts as one of its GD++ class.
- A `const` object can't be cast to a trait.

```gd++
if (auto target = body as Gd<Damageable>) {
  target->take_damage(10);
}
```

See `gd++ man traits`.

# Cost

- Static conversions cost nothing, like `static_cast`.
- A downcast asks the object for its class: cheap, but not free. In hot loops, keep the result instead of casting again.
- So does a checked cast to a trait, which also looks the class up among those that implement traits.
- Converting to or from a `Variant` packs or unpacks the value.
