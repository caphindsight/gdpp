Types: Godot types in C++

GD++ uses Godot's type system: the types you write in declarations are Godot's, e.g. `int`, `Vector3` or `Node`. Each one maps to exactly one C++ type, which the generated code uses, and which your C++ code works with. This page lists them all.

# Where types appear

Types appear in declarations only: in variables, function parameters and return values, signal parameters, and as the element types of typed arrays and dictionaries.

```gd++
var speed: float
func hit(target: Node3D, damage: int = 1) -> bool { ... }
signal scored(points: int, by: Player)
```

A missing type means `Variant`, which holds any value:

```gd++
var anything              // a Variant
func log(value) -> void   // value is a Variant
func get_any()            // returns a Variant
```

GD++ doesn't infer types, so `var x := 5` is an error: write `var x: int = 5`.

`void` is only allowed as a return type, and means that the function returns nothing.

# The mapping

```
GD++ type                     C++ type                       passed as
bool                          bool                           bool
int                           int64_t                        int64_t
float                         double (float64_t)             double
Variant, or no type           Variant                        const Variant &
String, StringName, NodePath  the same name                  const T &
Vector2, Vector3, Color, ...  the same name                  const T &
Array, Dictionary             the same name                  const T &
PackedByteArray, ...          the same name                  const T &
Array[T]                      TypedArray<T>                  const TypedArray<T> &
Dictionary[K, V]              TypedDictionary<K, V>          const TypedDictionary<K, V> &
Node, Node3D, Object, ...     Node *, Node3D *, ...          the pointer
RefCounted, Resource, ...     Ref<Resource>, ...             const Ref<T> &
your GD++ classes             like their base: Player * or Ref<Stats>
your GD++ enums               the C++ enum class             by value
externs                       gdpp::ExtPtr<T> or ExtRef<T>   by value
Async[T], Async               gdpp::Async<T>, Async<Variant> by value
Weak[T]                       gdpp::Weak<T>                  by value
```

"Passed as" is how function parameters and setters take the type. Return values and fields always use the plain C++ type.

Godot's `float` is a 64-bit `double`. The runtime header defines `float64_t` as a name for `double`, to match `int64_t`. Note that godot-cpp's own vector types use `real_t`, which is `float` in default builds, so e.g. the components of a `Vector3` are 32-bit.

# Classes

Any class of the package's API spec is a type, e.g. `Node`, `Camera3D`, `Resource` or `Texture2D`, and so is any class that a GD++ file of the package declares.

- A class that extends `RefCounted` is used through a reference, `Ref<T>`, which keeps the object alive. Godot deletes the object when the last reference goes away.
- Any other class, i.e. `Object` and all nodes, is used through a pointer, `T *`. The pointer doesn't keep the object alive: the object lives until someone deletes it, e.g. a node until it or its parent is freed.

```gd++
var camera: Camera3D        // Camera3D *camera;
var mesh: Mesh              // Ref<Mesh> mesh;

func use() -> void {
  camera->make_current();
  if (mesh.is_valid()) {
    gd::print(mesh->get_surface_count());
  }
}
```

Pointers start as `nullptr`, and references as null references.

GD++ only knows the classes of the package's API spec, so the spec's Godot version decides which classes you can use.

# Typed arrays and dictionaries

```gd++
var enemies: Array[Enemy]                  // TypedArray<Enemy>
var scores: Array[int]                     // TypedArray<int64_t>
var names: Dictionary[String, Node3D]      // TypedDictionary<String, Node3D>
```

`Array[T]` is an array that only holds values of type `T`. `Dictionary[K, V]` is a dictionary with keys of type `K` and values of type `V`. In C++, they are godot-cpp's `TypedArray` and `TypedDictionary`, with the element types spelled by name: `TypedArray<Node>`, not `TypedArray<Node *>`.

- Only `Array` and `Dictionary` take type arguments (and `Async` and `Weak`, see below): `Array` takes one, and `Dictionary` two.
- Element types can be built-in types and classes, but not enums, externs, `Async` or `Weak` types.
- Typed collections can't be nested: `Array[Array[int]]` is an error. Use `Array[Array]` instead.

Typed dictionaries need Godot 4.4 or newer.

# Enums

A GD++ enum declared in any GD++ file of the package is a type:

```gd++
enum Suit { DIAMONDS, CLUBS, SPADES, HEARTS }

var trump: Suit                // Suit trump;
func play(suit: Suit) -> void { ... }
```

In C++, it's an enum class with `int64_t` values, e.g. `Suit::HEARTS`. Godot sees it as an `int`, marked as an enum of the class, or as a bitfield for a `@bitfield` enum. See `gd++ man enums`.

Godot's own enums, e.g. `Error`, `Key` or `Node.ProcessMode`, aren't GD++ types. Declare GD++ enums that copy all their values instead, and convert them with `as` in C++ to pass them to the engine:

```gd++
enum ProcessMode { extends Node.ProcessMode }

func set_mode(mode: ProcessMode) -> void {
  set_process_mode(mode as Node::ProcessMode);
}
```

Global enums, e.g. `Error` or `Key`, need a new name, since Godot's names are taken: `enum KeyCode { extends Key }`. Or use `int`, and convert with `as` in C++. See `gd++ man enums`.

# Externs

An extern declared in any GD++ file of the package is a type. In C++, it's a `gdpp::ExtPtr<T>`, or a `gdpp::ExtRef<T>` if its base class is refcounted. It calls the members of the object by name, and converts to the externs it extends. Godot sees it as its base class. See `gd++ man externs`.

# Async

`Async[T]` is a task whose result has type `T`, e.g. a call of an `@onthread` function, which runs on another thread. `Async[void]` has no result, and a plain `Async` has a `Variant` result. Godot sees the task as an object of the package's class of tasks, e.g. `FooAsync` for a package whose prefix is `Foo`. In C++, it's a `gdpp::Async<T>`, a reference to that object. Copies share the task, so it can be passed around, stored in variables, and sent in signals, like any refcounted object.

`Async` types can't be exported, typed collections can't hold them, and a task's result can't be another task. See `gd++ man async`.

# Weak references

A plain pointer to a node, e.g. `Enemy *`, says nothing about whether the node still exists: once it's freed, the pointer points to freed memory, and using it crashes the game. A refcounted object, e.g. a `Mesh`, has the opposite problem: it lives as long as something references it, so a cache that holds it keeps it alive. `Weak[T]` is a reference to an object of the class `T` that doesn't keep it alive, and knows when it's gone:

```gd++
var target: Weak[Enemy]

func aim(enemy: Enemy) -> void {
  target = enemy;
}

func _process(delta: float) -> void {
  if (Enemy *e = target) {
    look_at(e->get_global_position());
  }
}
```

In C++, it's a `gdpp::Weak<T>`, which holds the object's ID, not the object. It converts to the object wherever one is needed, like in `Enemy *e = target`: it looks the object up by its ID, and gives `nullptr` once the object is freed. `if (target)` checks the same. For a `@pool` class, it also gives `nullptr` once the object is returned to its pool, even though the object still exists there, so a reference never points to a reused object. See `gd++ man pools`.

`T` can be any class. A `Weak` of a class that isn't refcounted, e.g. a node, converts to a `T *`, and a `Weak` of a refcounted class, e.g. a resource, to a `Ref<T>`:

```gd++
var cache: Weak[ArrayMesh]

func mesh() -> ArrayMesh {
  Ref<ArrayMesh> m = cache;
  if (m.is_null()) {
    m = create ArrayMesh;
    cache = m;
  }
  return m;
}
```

The `Ref<T>` keeps the object alive while you hold it, like any `Ref`. The `T *` doesn't: if something frees the object while you use the pointer, that's undefined behavior, which usually crashes the game. So use the pointer only on the main thread, where a node goes away only at the end of the frame or when your own code frees it, and don't keep it anywhere, e.g. in a variable of the class: keep the `Weak` instead, and convert it again the next time. On other threads, the main thread can free the object at any time.

The conversion also gives what a `T *` or a `Ref<T>` converts to, e.g. a base class, as in `Node *n = target;`, and works with `as`, e.g. `cache as Ref<Mesh>`. Where C++ can't use it, e.g. `auto e = target;`, which keeps the `Weak`, `target.ptr()` gives the `T *`, and `cache.ref()` the `Ref<T>`, for a refcounted class only. `==` compares a `Weak` with another `Weak` of its class, a pointer or a `Ref`, and they're equal when they refer to the same object.

A `Weak` itself is safe to keep for as long as you like, and to share between threads. Godot sees a `Weak[T]` as a `T`, which is `null` once the object is gone. `Weak` types can't be exported, and typed collections can't hold them.

# Other names

godot-cpp declares more names than classes, e.g. `TypedArray`, `Ref`, `UtilityFunctions` or `memnew`. Your C++ code can use them all, and GD++ includes their headers. But they aren't GD++ types:

```out
[×] res://a.gd++:3:8: TypedArray is not a Godot type.
     3 | var x: TypedArray
       |        ^^^^^^^^^^
    Hint: Types are Godot's built-in types and classes, and the package's classes, externs and enums.
```

Use `Array[T]` instead of `TypedArray<T>`, and a class name instead of `Ref<T>`.

# Unknown types

A misspelled type is an error, with a suggestion if a known type is close:

```out
[×] res://a.gd++:3:13: Unknown type "Vectr3".
     3 | var target: Vectr3
       |             ^^^^^^
    Hint: Did you mean "Vector3"?
```

# In Godot's documentation

The editor's help shows GD++ types like GDScript does: `int`, `float`, `Vector3`, `Node3D`, `int[]` for `Array[int]`, `Dictionary[String, Node3D]`, and the class of tasks, e.g. `FooAsync`, for `Async` types, and `T` for `Weak[T]`. Enums show as `int`, with the enum's name. See `gd++ man docs`.
