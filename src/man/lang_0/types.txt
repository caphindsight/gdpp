Types: Godot types in C++

GD++ uses Godot's type system.

- Types in declarations are Godot's, e.g. `int`, `Vector3` or `Node`.
- Each one maps to exactly one C++ type, which the generated code and your C++ code use.

This page lists them all.

# Where types appear

Only in declarations:

- variables,
- function parameters and return values,
- signal parameters,
- element types of typed arrays and dictionaries.

```gd++
var speed: float
func hit(target: Node3D, damage: int = 1) -> bool { ... }
signal scored(points: int, by: Player)
```

A missing type means `Variant`, which holds any value:

```gd++
var anything              // a Variant
func log(value) -> void   // value is a Variant
func get_any()            // returns a Variant
```

- GD++ doesn't infer types. `var x := 5` is an error: write `var x: int = 5`.
- `void` is only a return type. It means the function returns nothing.

# The mapping

```
GD++ type                     C++ type                       passed as
bool                          bool                           bool
int                           int64_t                        int64_t
float                         double (float64_t)             double
Variant, or no type           Variant                        const Variant &
String, StringName, NodePath  the same name                  const T &
Vector2, Vector3, Color, ...  the same name                  const T &
Array, Dictionary             the same name                  const T &
PackedByteArray, ...          the same name                  const T &
Array[T]                      TypedArray<T>                  const TypedArray<T> &
Dictionary[K, V]              TypedDictionary<K, V>          const TypedDictionary<K, V> &
Node, Node3D, Object, ...     Gd<Node>, Gd<Node3D>, ...      by value
RefCounted, Resource, ...     Gd<RefCounted>, ...            const Gd<T> &
your GD++ classes             Gd<Player>, Gd<Stats>, ...     like their base
your GD++ enums               the C++ enum class             by value
externs, traits               Gd<Terrain>, Gd<Damageable>    like their base
Async[T], Async               Async<T>, Async<Variant>       by value
Weak[T]                       Weak<T>                        by value
GpuArray[T]                   GpuArray<T>                    const GpuArray<T> &
```

- "Passed as": how function parameters and setters take the type.
- Return values and fields always use the plain C++ type.
- Every object type is a `Gd<T>`, whatever its kind. See "Objects" below.
- Godot's `float` is a 64-bit `double`. The runtime header defines `float64_t` as `double`, to match `int64_t`.
- godot-cpp's vector types use `real_t`, which is `float` in default builds. So e.g. the components of a `Vector3` are 32-bit.

# Classes

Class types:

- every class of the package's API spec, e.g. `Node`, `Camera3D`, `Resource` or `Texture2D`,
- every class that a GD++ file of the package declares.

In C++, every class is held as a `Gd<T>`, e.g. `Gd<Camera3D>`. See "Objects" below.

```gd++
var camera: Camera3D        // Gd<Camera3D> camera;
var mesh: Mesh              // Gd<Mesh> mesh;

func use() -> void {
  camera->make_current();
  if (mesh) {
    gd::print(mesh->get_surface_count());
  }
}
```

GD++ only knows the classes of the package's API spec. So the spec's Godot version decides which classes you can use.

# Typed arrays and dictionaries

```gd++
var enemies: Array[Enemy]                  // TypedArray<Enemy>
var scores: Array[int]                     // TypedArray<int64_t>
var names: Dictionary[String, Node3D]      // TypedDictionary<String, Node3D>
```

- `Array[T]`: an array that only holds values of type `T`.
- `Dictionary[K, V]`: a dictionary with keys of type `K` and values of type `V`. Needs Godot 4.4 or newer.
- In C++, they are godot-cpp's `TypedArray` and `TypedDictionary`, with element types spelled by name: `TypedArray<Node>`, not `TypedArray<Node *>`.
- Only `Array` (one argument) and `Dictionary` (two) take type arguments, besides `Async` and `Weak` (see `gd++ man async` and `gd++ man weak`).
- Element types can be built-in types and classes. Not enums, externs, traits, `Async` or `Weak` types.
- No nesting: `Array[Array[int]]` is an error. Use `Array[Array]`.

# Enums

A GD++ enum declared in any GD++ file of the package is a type:

```gd++
enum Suit { DIAMONDS, CLUBS, SPADES, HEARTS }

var trump: Suit                // Suit trump;
func play(suit: Suit) -> void { ... }
```

- In C++: an enum class with `int64_t` values, e.g. `Suit::HEARTS`.
- In Godot: an `int`, marked as an enum of the class, or as a bitfield for a `@bitfield` enum.
- See `gd++ man enums`.

Godot's own enums, e.g. `Error`, `Key` or `Node.ProcessMode`, aren't GD++ types. Instead:

- Declare a GD++ enum that copies all their values, and convert it with `as` in C++ to pass it to the engine.
- Global enums, e.g. `Error` or `Key`, need a new name, since Godot's names are taken: `enum KeyCode { extends Key }`.
- Or use `int`, and convert with `as` in C++.

```gd++
enum ProcessMode { extends Node.ProcessMode }

func set_mode(mode: ProcessMode) -> void {
  set_process_mode(mode as Node::ProcessMode);
}
```

See `gd++ man enums`.

# Externs

An extern declared in any GD++ file of the package is a type.

- In C++: a `Gd<T>`, e.g. `Gd<Terrain>`.
- It calls the object's members by name, and converts to the externs it extends.
- In Godot: its base class.
- See `gd++ man externs`.

# Traits

A trait declared in any GD++ file of the package is a type.

- In C++: a `Gd<T>`, e.g. `Gd<Damageable>`.
- It holds an object whose class implements the trait, and calls the trait's functions directly.
- In Godot: its base class. An object whose class doesn't implement the trait arrives as null.
- See `gd++ man traits`.

# Objects

In C++, `Gd<T>` holds an object of any kind: a class, refcounted or not, an extern or a trait.

- It's the C++ type of every class, extern and trait in declarations, e.g. `Gd<Node3D>` for `Node3D`.
- Your C++ code uses it too: `Gd<Player> player = create Player;`.
- Its API is the same for every kind:
  - it starts as null, and tests as a `bool`: `if (player) { ... }`,
  - `->` calls the object's members,
  - `ptr()` gives the object as a plain pointer,
  - it converts to and from pointers and `Ref`s, so it passes to godot-cpp's functions.
- For a refcounted class, it keeps the object alive, like a `Ref`. Godot deletes the object when the last one goes away.
- For other classes, it doesn't. The object lives until someone deletes it, e.g. a node until it or its parent is freed.
  - Then `Gd<T>` costs what a pointer does: the compiler generates the same code.
- See `gd++ man runtime`.

# Async

`Async[T]` is a task whose result has type `T`, e.g. a call of an `@onthread` function, which runs on another thread.

- `Async[void]` has no result. A plain `Async` has a `Variant` result.
- In Godot: an object of the package's class of tasks, e.g. `FooAsync` for the prefix `Foo`.
- In C++: an `Async<T>`, a reference to that object.
- Copies share the task. Like any refcounted object, it can be passed around, stored in variables, and sent in signals.
- It can't be exported.
- Typed collections can't hold it.
- A task's result can't be another task.
- See `gd++ man async`.

# GPU arrays

`GpuArray[T]` is an array that stays on the GPU, where shaders read and write it, e.g. `GpuArray[float]`.

- T is `float`, `int`, `Vector2`, `Vector3`, `Vector4` or `Color`.
- In C++: a `GpuArray<T>`, with an `int32_t` for `int`, e.g. `GpuArray<int32_t>`.
- In Godot: an object of the package's class of GPU arrays, e.g. `FooGpuArray` for the prefix `Foo`.
- Copies share the array.
- It can't be exported, and typed collections can't hold it.

Shaders also take `Texture2D[FORMAT]`, a texture that they write, and return `Image[FORMAT]` and `Texture2D[FORMAT]`, e.g. `Texture2D[rgba8]`. Those are a `Texture2D` and an `Image` with a format, which only shaders' signatures use. See `gd++ man shaders`.

# Weak references

`Weak[T]` is a reference to an object of the class `T` that:

- doesn't keep it alive,
- knows when it's gone: once a node is freed, a refcounted object is freed, or a pooled object is returned to its pool.

See `gd++ man weak`.

# Other names

godot-cpp declares more than classes, e.g. `TypedArray`, `Ref`, `UtilityFunctions` or `memnew`.

- Your C++ code can use them all, and GD++ includes their headers.
- They aren't GD++ types:

```out
[×] res://a.gd++:3:8: TypedArray is not a Godot type.
     3 | var x: TypedArray
       |        ^^^^^^^^^^
    Hint: Types are Godot's built-in types and classes, and the package's classes, externs, traits and enums.
```

- Use `Array[T]` instead of `TypedArray<T>`, and a class name instead of `Gd<T>`.

# Unknown types

A misspelled type is an error, with a suggestion if a known type is close:

```out
[×] res://a.gd++:3:13: Unknown type "Vectr3".
     3 | var target: Vectr3
       |             ^^^^^^
    Hint: Did you mean "Vector3"?
```

# In Godot's documentation

The editor's help shows GD++ types like GDScript does:

- `int`, `float`, `Vector3`, `Node3D`,
- `int[]` for `Array[int]`,
- `Dictionary[String, Node3D]`,
- the class of tasks, e.g. `FooAsync`, for `Async` types,
- `T` for `Weak[T]`,
- `int` with the enum's name, for enums.

See `gd++ man docs`.
