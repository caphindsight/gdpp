Externs: other packages' classes at runtime

Each package is compiled on its own. So its code can't use another package's classes: the C++ compiler never sees them. An extern solves this at runtime:

- It declares a class that lives somewhere else.
- Your code uses it like any other class.
- Calls to its members go by name.

# Declaring an extern

```gd++
extern Terrain {
  extends Node3D
  func height_at(x: float, z: float) -> float
  @const func size() -> int
  @deferred func rebuild() -> void
  var seed: int
  signal changed
}
```

An extern lists what your code needs of the class: its base class, and some of its functions, variables and signals, with their types, as the class declares them.

The class can be anything that Godot knows by that name at runtime:

- a GD++ class of another package,
- a class of any other GDExtension, written with GD++ or not,
- a GDScript class with a `class_name`, or a class of any other scripting language.

Names:

- The extern's name must be the class's name.
- It must not name a class the package already knows. Godot's classes and the package's own classes are used directly.

Externs can be file-level, with `extern_name`, or inline, like classes. See `gd++ man files`.

# Base class

`extends` names the extern's base class: a Godot class, a GD++ class of the package, or another extern. Without `extends`, it extends `RefCounted`. The base decides:

- What your code can do with the object without calling by name: everything the base class can.
- How the extern is used: through a pointer, `ExtPtr<Terrain>`, if the base isn't refcounted, or through a reference, `ExtRef<Terrain>`, if it is.
- How Godot sees it: as an object of the base class.

Use the class's real base class, or any class above it, e.g. `Node3D` or `Node`, as long as the object really is one.

An extern that extends another extern:

- has that extern's members too,
- converts to it, e.g. to pass an `ExtPtr<Car>` where an `ExtPtr<Vehicle>` is expected.

```gd++
extern Vehicle {
  extends Node3D
  func speed() -> float
}

extern Car {
  extends Vehicle
  func honk() -> void
}
```

The chain of bases must end with a Godot class or a GD++ class of the package, e.g. `Node3D` here. That class decides the three points above.

# Members

Externs can only declare:

func
  Functions, without a body or default values.
  - They can have `@const`, `@deferred`, `@thread_safe`, `@rpc` without arguments, `@trace` and `@profile`.
  - Not `@onthread`.
  - The return type must match what the class returns.

var
  Variables, without an initial value or a property body.
  - Read with `get_NAME()`, written with `set_NAME(value)`.
  - They can have `@profile`, and `@readonly`, which leaves out `set_NAME`.

signal
  Signals, to send them on the object, with `emit`. They can have `@trace`.

The extern itself can have:

- `@factory`, to make `create`, `destroy` and `queue_destroy` call its class's methods. See "Factory methods" below.
- `@trace` and `@profile`, for all its members. See "Externs" in `gd++ man debugging`.

Facts:

- Anything else, e.g. `ctor`, `dtor`, `on` blocks, enums, `decl` and `impl` blocks, is an error: "Externs can't contain ...".
- Declare only the members your code uses.

# Using an extern

An extern is a type, like a class:

```gd++
class_name Car
extends Node3D

@export var terrain: Terrain

on physics_process(delta: float) {
  Vector3 pos = get_position();
  pos.y = terrain->height_at(pos.x, pos.z);
  set_position(pos);
}

func regenerate(seed: int) -> void {
  terrain->set_seed(seed);
  terrain->rebuild();
  emit terrain->changed();
}
```

- Functions: `terrain->height_at(x, z)` calls `height_at` on the object, by name, and converts the result to the declared return type.
- Variables: `terrain->get_seed()` and `terrain->set_seed(5)` get and set the property by name.
- Signals: `emit terrain->changed()` emits the signal on the object.
- The base class: `terrain.base()` returns the object as its base class, `Node3D *`, for anything else, e.g. `add_child(terrain.base())` or `terrain.base()->get_position()`.

In C++, an `ExtPtr<T>`:

- starts as null,
- can be set from a pointer to the base class or `nullptr`: `terrain = get_node<Node3D>("Terrain");`,
- tests as a bool: `if (terrain) { ... }`,
- compares with `==` to another `ExtPtr<T>`,
- converts to a `Variant`, e.g. to pass it to Godot.

Also:

- An `ExtRef<T>` is the same, but holds a reference, which keeps the object alive. Its `base()` returns a `Ref<Base>`.
- `Ext<T>` is whichever of the two fits `T`.
- Converting a base class pointer to an extern doesn't check the object's class. If it's not really a `Terrain`, calls fail at runtime, with Godot's errors about missing methods.
- For exported variables, the editor checks it for you. See below.

# Exported externs

```gd++
@export var terrain: Terrain
```

- In Godot, the variable's type is the base class, `Node3D`.
- If the base is a `Node` or a `Resource`, the editor only accepts objects whose class is named `Terrain`: the node picker only offers `Terrain` nodes, and the resource picker only `Terrain` resources.
- That's the usual way to connect objects of different packages: in the editor, not in code.

# Creating and deleting objects

```gd++
Ext<Terrain> terrain = create Terrain;
add_child(terrain.base());

destroy some_terrain;             // only for ExtPtr; refcounted objects delete themselves
```

`create T` creates an object of the class named like the extern:

- a class that Godot's `ClassDB` knows, e.g. of a GDExtension,
- or else a global script class, i.e. a script with a `class_name`: it loads it and calls `new()` on it.
- If there's no such class, it prints an error and returns null.

`destroy`:

- deletes an `ExtPtr`'s object,
- doesn't compile for an `ExtRef`: refcounted objects delete themselves when their last `ExtRef` goes away.

They're the same `create` and `destroy` as for any class. See `gd++ man classes`. To call the class's own methods instead, see the next section.

# Factory methods

With `@factory`, `create`, `destroy` and `queue_destroy` call methods of the extern's class, by name, instead:

```gd++
@factory
extern Bullet {
  extends Area3D
}
```

- `create Bullet` calls the class's static method `create()`, and returns its result. It may be null, e.g. from a full `"fixed"` pool. Always check it.
- `destroy bullet` calls the object's method `destroy()`.
- `queue_destroy bullet` calls the object's method `queue_destroy()`.

That's how other packages use a GD++ class's pool or scene: give the class `@factory` too, and its methods do the work in the class's own package. See `gd++ man classes` and `gd++ man pools`.

Other names: `@factory` takes up to three strings, for `create`, `destroy` and `queue_destroy`, in this order, like on a class. An empty string `""`, or a missing name at the end, keeps the default for that one:

```gd++
@factory("spawn", "", "queue_despawn")    # create calls spawn(), destroy deletes, queue_destroy calls queue_despawn()
```

Facts:

- Only the methods that apply: no `destroy` for refcounted externs, and no `queue_destroy` for externs that don't extend `Node`.
- An extern that extends a `@factory` extern doesn't use its methods, unless it has `@factory` itself.
- Externs can't have `@pool`, `@scene`, `@factory_pool` or `@factory_scene`. Declare the class's other methods as members, like any other.

# @deferred

```gd++
extern Terrain {
  extends Node3D
  @deferred func rebuild() -> void
}
```

- Calls to a `@deferred` function go through `call_deferred` instead of `call`: they run at the end of the frame. So `@deferred` functions must return `void`.
- `@thread_safe` is the same, with `call_thread_safe`. It needs an extern that extends `Node`.
- Classes have `@deferred` and `@thread_safe` too, which defer every call, not only those through the extern. If the class already defers the function, its extern doesn't need to.

See `gd++ man functions`.

# @onthread functions

```gd++
extern Planner {
  extends Node
  func plan(steps: int) -> Async[Array]
}
```

- An `@onthread` function of another package returns a task. Its extern declares an `Async` as the return type, without `@onthread`: the class already runs every call on a worker thread.
- A call returns an `Async<Array>`, which works like the tasks of your own package. See "Across packages" in `gd++ man async`.
- An `@onthread("detached")` function returns nothing. Its extern declares it as a plain `void` function: `func save(slot: int) -> void`.

# @rpc

```gd++
extern Lobby {
  extends Node
  @rpc func join(name: String) -> void
}

rpc(1) lobby->join("Me");
```

- An `@rpc` function of an extern can be called over the network with `rpc`, like one of your own classes.
- It takes no arguments: the class that defines the function configures it.
- The extern must extend `Node`.

See `gd++ man rpc`.

# Speed

Every call on an extern goes through Godot's `call` by name:

- the arguments are packed into `Variant`s,
- the method is looked up by name,
- the result is unpacked.

That's much slower than a C++ call, though the names are interned only once. Use externs where you need them, e.g. to connect packages, not in hot loops.

# How it works

- For each extern, GD++ generates a header, e.g. `Terrain.h`, with a small wrapper class in namespace `godot`.
- The wrapper holds a pointer to the object. It has a method for each declared member, which calls the object's `call`, `call_deferred`, `get`, `set` or `emit_signal` with the member's name.
- `ExtPtr<T>` and `ExtRef<T>` hold the object. Their `operator->` returns such a wrapper.
- Externs aren't registered with Godot: they're only names for classes registered elsewhere.

See `gd++ man runtime` and `gd++ man generated`.

# Example

Two packages: `res://world` builds the terrain, and `res://vehicles` uses it.

`res://world/terrain.gd++`:

```gd++
class_name Terrain
extends Node3D

signal changed

func height_at(x: float, z: float) -> float {
  return Math::sin(x) * Math::cos(z);
}
```

`res://vehicles/terrain.gd++`:

```gd++
extern_name Terrain
extends Node3D

func height_at(x: float, z: float) -> float
signal changed
```

`res://vehicles/car.gd++`:

```gd++
class_name Car
extends Node3D

@export var terrain: Terrain

on process(delta: float) {
  if (!terrain) {
    return;
  }
  Vector3 pos = get_position();
  pos.y = terrain->height_at(pos.x, pos.z);
  set_position(pos);
}
```
