gd++ cat: show files, highlighted

# Synopsis

```sh
gd++ cat FILE...
gd++ cat --svg FILE
```

# Description

Shows any files, in the pager when they don't fit the terminal. The files don't have to be part of a project. Several files are shown one after another, each after a gray line naming it, e.g. `// ==== src/player.gd++ ====`, like in `gd++ trans`. For the pager's keys, see `gd++ man cli`.

On a terminal, C++ and GD++ files are highlighted: keywords, types, functions, literals and comments get their own colors. GD++'s rewrites in C++ code show as keywords too: `emit`, `rpc`, `is_cancelled` and `assert` everywhere, `is_done`, `claim`, `cancel` and `as` only where a name follows them, and `string_name` only where a string follows it, so a plain call like `task.is_done()` shows as a call. See `gd++ man rewrites`.

A file is C++ if its extension is `.c`, `.cc`, `.cpp`, `.cxx`, `.c++`, `.h`, `.hh`, `.hpp`, `.hxx`, `.h++` or `.inl`, and GD++ if it's `.gd++`, `.gdpp` or `.gg`. Other files are shown as they are. When the output is not a terminal, e.g. in `gd++ cat player.gd++ | grep func`, files are printed as plain text, without the pager.

With `--svg`, the file is printed as an SVG image instead: highlighted the same way, on a dark background, whether or not the output is a terminal. GitHub, for one, can't highlight GD++, but it shows SVG images in a README. The image shows tabs as `--tab-width` columns, and leaves out control characters and the trailing empty lines.

# Arguments and options

FILE...
  The files to show, at least one. With `--svg`, exactly one.

--svg
  Print the file as a highlighted SVG image, rather than show it.

# Examples

```sh
gd++ cat src/player.gd++                      # a GD++ file
gd++ cat my_package/.gd++pkg/gdpp/Player.cpp  # the C++ that GD++ generated
gd++ cat notes.txt                            # any other file, as it is
gd++ cat src/*.gd++                           # all GD++ files in src
gd++ cat --svg src/player.gd++ > player.svg   # an image of a GD++ file
```
