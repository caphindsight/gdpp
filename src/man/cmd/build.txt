gd++ build: compile packages

# Synopsis

```sh
gd++ build [PATH...] [--for PLATFORM.ARCH...] [-w] [-p PLATFORM] [--arch ARCH]
           [--ship] [--opt | --small | --noopt] [--doc | --nodoc] [--nowarn] [--nogpu] [-j N] [--clean]
           [--cc COMPILER] [--asan] [--ubsan] [--tsan] [--macro-timeout SECONDS]
           [--trace GROUP...] [--profile GROUP... [--print [--period SECONDS] [--fps FPS]]]
```

# Description

- Builds the package that contains each PATH into GDExtension libraries, one per target.
- Builds the packages one after another, in the order of the paths.
- Writes them into the package root, with the package's `.gdextension` file. Godot loads them from there.
- Writes a missing `.gdignore` file into each package's hidden directories. See `hide` in `gd++ man packages`.
- To build the whole project, run `gd++ build res://...`.
- Keeps GD++'s exclude filters in the project's export presets up to date, as the `presets` setting in `.gd++proj` says. See `gd++ man shipping`.

For how builds work, targets, and debug and release builds in depth, see `gd++ man building`.

# Options

PATH...
  Build the packages that contain these paths. Default: `...`.
  - `DIR/...` builds every package in `DIR`, sorted by path, e.g. `res://...` the whole project, and `...` or `./...` the current directory.
  - At the root of a package without nested packages, `...` builds just that package.
  - Each package is built once.
  - All packages must be in one Godot project.

--for PLATFORM.ARCH...
  Build for each of these targets, e.g. `windows.x86_64` or `w.x64`.
  - Platforms: `windows` (`win`, `w`), `linux` (`lin`, `l`), `macos` (`mac`, `m`).
  - Architectures: `x86_32` (`x32`), `x86_64` (`x64`), `arm64` (`a64`).
  - Duplicates are built once.
  - Default: this machine. Not with `-w`, `--platform` or `--arch`.

-p PLATFORM, --platform PLATFORM
  Build for this platform: `windows`, `linux` or `macos`, or their short names. The architecture is that of `--arch`, or else this machine's. Default: this machine's platform.

-w
  Short for `--platform windows`.

--arch ARCH
  Build for this CPU architecture: `x86_32`, `x86_64` or `arm64`, or their short names. Default: this machine's.

--ship
  Build for release: godot-cpp's `template_release` target, with link-time optimization, optimized for speed, without documentation. The default is a debug build: godot-cpp's `template_debug` target, a dev build with debug symbols and hot reload, unoptimized, with documentation.

--opt
  Optimize for speed. Default with `--ship`.

--small
  Optimize for binary size.

--noopt
  Don't optimize. Default without `--ship`.

--doc
  Compile the documentation of GD++ classes into the library, for the editor's help. Default without `--ship`.

--nodoc
  Don't compile the documentation. Default with `--ship`.

--cc COMPILER
  Compile with this C++ compiler: `gcc`, `clang`, `msvc` or `clang-cl`. For Windows, `gcc` and `clang` are MinGW-w64's. Default: godot-cpp's for the target. See "Compilers" in `gd++ man building`.

--nowarn
  Disable C++ warnings: `-w`, or `/w` with MSVC. By default, warnings are errors: `-Werror`, or `/WX` with MSVC. Either way, it applies to the package's C++ and the generated C++, not to godot-cpp.

--nogpu
  Run shaders on the CPU, even with a GPU, e.g. to step through their bodies in a debugger. See "Without a GPU" in `gd++ man shaders`.

--trace GROUP...
  Compile in the `@trace` annotations of these groups, or of all groups with `all`.
  - An annotation is in the group named after its class, and in the groups that its arguments name.
  - The groups `process` and `physics_process` also trace all `on process` and `on physics_process` blocks, and overrides of `_process` and `_physics_process`, without annotations.
  - Other `@trace` annotations generate nothing.
  - See `gd++ man debugging`.

--profile GROUP...
  Compile in the `@profile` annotations of these groups, or of all groups with `all`, like `--trace` does for `@trace`. Their timings show in the editor's Debugger > Monitors tab. See `gd++ man debugging`.

--print
  With `--profile`, also print a table of timings every few seconds while the game runs.

--period SECONDS
  With `--print`, the seconds between tables. Default: 10.

--fps FPS
  With `--print`, the frame rate that the table's budget column assumes. Default: 60.

--macro-timeout SECONDS
  Stop a macro or template invocation that runs longer than this, with an error. Default: 20. See `gd++ man templates` and `gd++ man macros`.

--asan
  Detect memory errors, e.g. use after free or out-of-bounds access, with AddressSanitizer. See "Sanitizers" in `gd++ man building`.

--ubsan
  Detect undefined behavior, e.g. signed integer overflow, with UndefinedBehaviorSanitizer. Not supported by MSVC.

--tsan
  Detect data races between threads, with ThreadSanitizer. Not supported by MSVC.

-j N, --jobs N
  Run N compile jobs at once. Default: one per CPU core, minus one.

--clean
  Clean each package first, like `gd++ clean --bin`: delete its build cache, libraries and `.gdextension` files. The build starts from scratch.
  - Skips packages without a build cache: they build from scratch anyway.

Rules:

- At most one of `--opt`, `--small` and `--noopt`.
- At most one of `--doc` and `--nodoc`.
- Not `--asan` with `--tsan`.
- `--cc` must build for every target.
- Group names are made of letters, digits and underscores.
- `--print` needs `--profile`. `--period` and `--fps` need `--print`.

# Output

First, once, the build parameters. Then a task per package:

```out
[•] Build parameters: windows.x86_64, release, optimized, no docs.
[•] Building res://gameplay.
```

The parameters:

- Always: the targets, debug or release, and the optimization.
- If set: the `--cc` compiler, disabled warnings, and the sanitizers.
- If a package has GD++ files: whether docs are compiled, which groups `--trace` turns on, and whether profiling is on.
- On a terminal, the parts that differ from the defaults are highlighted.

Other lines:

- With several targets, a task per package and target, e.g. "Building res://gameplay for windows.x86_64...".
- "Registering classes for ...": the package's list of classes changed.
- "Generating .gdextension for ...": the `.gdextension` file changed.

Files written into the package root, where `<id>` is the name of the package's directory:

```
lib<id>.<platform>.<debug|release>.<arch>.<so|dll|dylib>
<id>.gdextension
<id>.gdextension.uid
```

# Examples

Build every package in the current directory, for this machine, in debug mode:

```sh
gd++ build
```

Build another package:

```sh
gd++ build tools/level_editor
```

Build everything for release, for Linux and Windows:

```sh
gd++ build res://... --ship --for l.x64 w.x64
```

Build for Windows on a Linux machine:

```sh
gd++ build -w
```

Make a fast debug build, e.g. to profile:

```sh
gd++ build --opt
```

Turn on the `@trace` annotations of the group `combat` and of the class `Player`:

```sh
gd++ build --trace combat Player
```

Profile everything in an optimized build, and print a table of timings every 10 seconds, with the frame budget of a 144 Hz screen:

```sh
gd++ build --opt --profile all --print --fps 144
```

Build code that has warnings, e.g. while trying something out:

```sh
gd++ build --nowarn
```

Look for memory errors and undefined behavior:

```sh
gd++ build --asan --ubsan
```

Build with Clang:

```sh
gd++ build --cc clang
```

Start over after a strange build error:

```sh
gd++ build --clean
```

# Errors

- "Missing Godot C++ bindings NAME, run `gd++ fetch --missing` to fix this." The package's dependencies aren't in the project.
- "Failed to find SCons, see https://scons.org to install it: ..." Run `gd++ install`.
- "Failed to detect the platform, use --platform to choose one." GD++ doesn't support this machine's platform or architecture. Name the target.
- "Invalid arguments: \"x\" is not a valid target, use PLATFORM.ARCH, e.g. windows.x86_64 or w.x64."
- "Invalid arguments: \"a-b\" is not a valid group name." A `--trace` or `--profile` group isn't a valid name.
- "Invalid arguments: --print needs --profile.", "--period needs --print." and "--fps needs --print." The option does nothing without the other one.
- "Invalid arguments: --period must be positive."
- "Invalid arguments: --asan and --tsan cannot be used together."
- "Invalid arguments: --cc msvc cannot build for linux." The compiler doesn't support a target. See "Compilers" in `gd++ man building`.
- "Invalid arguments: --cc clang cannot build for windows on this machine." MSVC and clang-cl only run on Windows. On Windows, godot-cpp only supports MinGW-w64's GCC.
- An error in a GD++ file, with its location and a hint. See `gd++ man errors`.
- "The name X is declared in both A and B." Two GD++ files of the package declare the same class, extern, trait or enum.
- "Class X is declared in FILE and in .gd++pkg." A GD++ class and a C++ class have the same name.
- The building task fails: the compiler or linker failed, and its whole output follows. Errors in the C++ code of GD++ files point to the GD++ files.
