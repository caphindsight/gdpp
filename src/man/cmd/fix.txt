gd++ fix: tidy up the project

# Synopsis

```sh
gd++ fix
```

# Description

Brings the project into its canonical state. It takes no options, and is always safe to run. It:

- Reformats `res://.gd++proj.toml`, if it exists, and every package's `.gd++pkg.toml` into the form that `gd++` writes. Classes in `.gd++pkg.toml` are sorted by name. Comments and unusual formatting are lost.
- Updates the GD++ blocks in the `.gitignore` files of the project and its packages to match the `vcs` setting: writes missing blocks, updates outdated ones, and removes them if the project doesn't use git. See `gd++ man vcs`.
- Adds GD++'s exclude filters to every preset in `res://export_presets.cfg`, like `gd++ build`, or removes them if the `presets` setting is off. See `gd++ man shipping`.
- Deletes `res://.gd++proj/temp`, the temporary files that an interrupted command may have left.
- Deletes empty dependency cache directories, e.g. `res://_gd++/engine` after the last engine was removed.
- Writes a missing `.gdignore` file into `res://_gd++`, `res://.gd++proj` and every package's build cache, so Godot skips them. `gd++` writes it whenever it creates these directories, so this is a last resort, e.g. if you deleted it by hand.

Output:

- Each change is logged, e.g. "Reformatted res://.gd++pkg.toml.".
- If nothing needed fixing, it says "The project is already tidy.".

Run it after upgrading `gd++`, after editing config files by hand, or after moving packages around.

# Example

```
gd++ fix
[•] Reformatted res://gameplay/.gd++pkg.toml.
[•] Created res://tools/.gitignore.
[•] Deleted the temporary directory res://.gd++proj/temp.
[•] Success!
```
