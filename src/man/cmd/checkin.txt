gd++ checkin: check dependencies in or out

# Synopsis

```sh
gd++ checkin [--bind NAME...] [--spec NAME...] [--engine NAME...]
             [--bind-all] [--spec-all] [--engine-all] [--undo]
gd++ checkin -a [--undo]
```

# Description

- Moves dependencies from the ephemeral cache, `res://.gd++cache`, to the checked in cache, `res://_gd++`, which you commit to version control.
- With `--undo`, moves them back, so they're ephemeral again.
- Packages find their dependencies in either cache, so builds don't change.
- A dependency already in the right cache stays there, with a warning. Its copy in the other cache, if any, is deleted.
- `gd++` checks that every named dependency exists before it moves anything. So a typo changes nothing.

See `gd++ man dependencies`.

# Options

--bind NAME...
  Check in these Godot C++ bindings.

--bind-all
  Check in all Godot C++ bindings.

--spec NAME...
  Check in these Godot API specs.

--spec-all
  Check in all Godot API specs.

--engine NAME...
  Check in these Godot engines.

--engine-all
  Check in all Godot engines.

-a, --all
  Check in all dependencies of all kinds. Not with the other options, except `--undo`.

--undo
  Make the dependencies ephemeral: move them from the checked in cache to the ephemeral one.

Rules:

- At least one option that chooses dependencies.
- Not `--bind` with `--bind-all`. The same for `--spec` and `--engine`.

# Examples

Commit the spec of a custom Godot build, so your team gets it with the repository:

```sh
gd++ checkin --spec my-4.7
git add _gd++
```

Check in all the project's dependencies:

```sh
gd++ checkin -a
```

Stop committing the bindings:

```sh
gd++ checkin --undo --bind 10.0.0-stable
```

# Errors

- "The Godot API spec NAME is not in the project cache." Fetch or vendor it first.
- "Invalid arguments: \"a/b\" is not a valid dependency name." Names are directory names, without slashes.
