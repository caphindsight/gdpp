gd++ ls: show a project overview

# Synopsis

```sh
gd++ ls [PATH] [--deps] [-l | -a]
```

# Description

Prints an overview of the project:

- its name and settings,
- the dependencies in its caches,
- its packages.

Packages:

- The package that contains PATH, or the current directory, is expanded: its dependencies, settings and classes are shown.
- Other packages take one line each.
- A project's only package is always expanded.

It's the quickest way to check a project's state, e.g. after cloning it. It shows missing and unused dependencies, missing files, and GD++ files with errors.

# Options

PATH
  Show the project that contains this path, and expand the package that contains it. Default: the current directory.

--deps
  List every dependency in the caches, instead of counting them.

-l, --pkgs
  Expand all packages.

-a, --all
  Show all details, like `--deps` and `--pkgs` together.

# Output

```
Project: My Game [my_game]
  Godot:           4.7
  VCS:             git
  Manage presets:  yes

Dependencies:
  Godot C++ bindings:  1 checked in  •  1 cached  •  1 unused
  Godot API specs:     1 cached

Package: res://gameplay
  Godot C++ bindings:  10.0.0-stable
  Godot API spec:      4.7.2-stable
  GD++ syntax:         1
  C++ standard:        c++20
  Class prefix:        Gameplay
  Quit timeout:        1 second
  Hot reload:          on
  Macro depth:         64

  Classes
    res://gameplay/spinner.h  Spinner                              @tool
    pkg://gizmo.gd++          Gizmo       extends Node3D           @tool
    pkg://player.gd++         Player      extends CharacterBody3D  @game_only @icon
                              Stats       extends Resource         @icon (missing)
    pkg://broken.gd++         has errors  see gd++ build

Package: res://tools  missing dependencies

To fix: gd++ fetch --missing
```

The parts:

Project:

- The name from `project.godot`, and the project's id (its directory name) in brackets.
- The Godot version from `project.godot`.
- The `vcs` setting from `.gd++proj`.
- "Manage presets": the `presets` setting from `.gd++proj`, "yes" or "no". See `gd++ man projects`.

Dependencies:

- Per kind: how many are checked in, cached (in the ephemeral cache) and unused (named by no package).
- With `--deps`: one row per dependency, newest first, with its cache and whether it's unused.
- Godot engines are shown only with `-a`.

Package:

- Its path, and for the root package, its id in brackets.
- An expanded package shows:
  - its bindings and spec, marked "missing" if the project doesn't have them,
  - its GD++ syntax, marked "(nightly, not for production)" if it's 0,
  - its C++ standard, class prefix, quit timeout and hot reload setting (see `gd++ man packages`),
  - its classes.
- A collapsed package shows "missing dependencies" if it lacks any.

Classes, a table with a row per class:

- The file declaring it, shown only on the file's first class.
- Its name.
- For a GD++ class, its base class, and the traits it implements itself, e.g. "extends Node3D implements Damageable". See `gd++ man traits`.
- Its tags:
  - `[ptr]` or `[ref]`: a C++ class that GD++ code can use. See `gd++ man cpp-classes`.
  - `@abstract`: it's only a base for other classes.
  - `@tool`: it runs in the editor too. Without it, it's a runtime class.
  - `@game_only`, `@editor_only` and `@icon`.
  - For GD++ classes, tags come from annotations. For C++ classes, from `.gd++pkg`.
  - Debugging annotations, like `@trace` and `@profile`, aren't shown.
- Order: the C++ classes from `.gd++pkg` first, those without a header first, then the classes of each GD++ file, in order.
- A missing header or icon is marked "(missing)".
- A class declared twice is marked "declared twice".
- A GD++ file with errors gets its own row at the end, marked "has errors", since its classes can't be read. Run `gd++ build`, or `gd++ trans` on the file, to see the error.

Other facts:

- If any package lacks dependencies, a hint at the end says how to fix it.
- Problems are shown in red.
- Without Unicode support, "•" is "*".
- The output goes to stdout, so you can save or search it, e.g. `gd++ ls -a > overview.txt`.

# Examples

```sh
gd++ ls                  # the project, with the package you're in expanded
gd++ ls tools            # with res://tools expanded
gd++ ls -a               # everything
gd++ ls -a ~/my_game     # everything, from outside the project
```
