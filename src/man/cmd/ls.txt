gd++ ls: show a project overview

# Synopsis

```sh
gd++ ls [PATH] [--deps] [-l | -a]
```

# Description

Prints an overview of the project: its name and settings, the dependencies in its caches, and its packages. The package that contains PATH, or the current directory, is expanded: its dependencies, settings and classes are shown. Other packages take one line each. If the project has only one package, it is always expanded.

It's the quickest way to check a project's state, e.g. after cloning it: it shows missing and unused dependencies, missing files, and GD++ files with errors.

# Options

PATH
  Show the project that contains this path, and expand the package that contains it. Default: the current directory.

--deps
  List every dependency in the caches, instead of counting them.

-l, --pkgs
  Expand all packages.

-a, --all
  Show all details, like `--deps` and `--pkgs` together.

# Output

```
Project: My Game [my_game]
  Godot:  4.7
  VCS:    git

Dependencies:
  Godot C++ bindings:  1 checked in  •  1 cached  •  1 unused
  Godot API specs:     1 cached
  Godot engines:       none

Package: res://gameplay
  Godot C++ bindings:  10.0.0-stable
  Godot API spec:      4.7.2-stable
  GD++ syntax:         1
  C++ standard:        c++20
  Class prefix:        Gameplay
  Quit timeout:        1 second
  Hot reload:          on

  Classes
    res://gameplay/spinner.h  Spinner                              @tool
    pkg://gizmo.gd++          Gizmo       extends Node3D           @tool
    pkg://player.gd++         Player      extends CharacterBody3D  @game_only @icon
                              Stats       extends Resource         @icon (missing)
    pkg://broken.gd++         has errors  see gd++ build

Package: res://tools  missing dependencies

To fix: gd++ fetch --missing
```

The parts:

- Project: the name from `project.godot`, the project's id (its directory name) in brackets, the Godot version from `project.godot`, and the `vcs` setting from `gd++proj.toml`. With `-a`, also "Manage presets": the `presets` setting from `gd++proj.toml`, "yes" or "no" (see `gd++ man projects`).
- Dependencies: per kind, how many are checked in, cached (in the ephemeral cache) and unused (named by no package). With `--deps`, one row per dependency, newest first, with its cache and whether it's unused.
- Package: the package's path, and for the root package, its id in brackets. An expanded package shows its bindings and spec, marked "missing" if the project doesn't have them, its GD++ syntax, marked "(nightly, not for production)" if it's 0, its C++ standard, class prefix and quit timeout (see `gd++ man packages`), and its classes.
- Classes: a table with a row per class: the file declaring it, shown only on the file's first class, its name, and for a GD++ class, its base class. First come the C++ classes from `gd++pkg.toml`, in order, those without a header first, then the classes of each GD++ file, in order. Each class is followed by its tags: for a C++ class, `[ptr]` or `[ref]` if GD++ code can use it (see `gd++ man cpp-classes`), then `@tool` (it runs in the editor too, and without it, it's a runtime class), `@game_only` and `@icon`, from its annotations, or for a C++ class, from `gd++pkg.toml`. Annotations for debugging, like `@trace` and `@profile`, aren't shown. A missing header or icon is marked "(missing)", and a class declared twice "declared twice". A GD++ file with errors gets a row of its own at the end, marked "has errors", since its classes can't be read: run `gd++ build`, or `gd++ trans` on the file, to see the error.

A collapsed package shows "missing dependencies" if it lacks any. If any package lacks dependencies, a hint at the end says how to fix it. Problems are shown in red.

Without Unicode support, "•" is "*".

The output goes to stdout, so you can save it or search it, e.g. `gd++ ls -a > overview.txt`.

# Examples

```sh
gd++ ls                  # the project, with the package you're in expanded
gd++ ls tools            # with res://tools expanded
gd++ ls -a               # everything
gd++ ls -a ~/my_game     # everything, from outside the project
```
