gd++ vendor: copy a dependency in or out

# Synopsis

```sh
gd++ vendor (--bind NAME | --spec NAME | --engine NAME) --from PATH [--tar | --zip] [--checkin]
gd++ vendor (--bind NAME | --spec NAME | --engine NAME) --to PATH [--tar | --zip]
```

# Description

Copies one dependency between the project's cache and your disk.

- `--from`: copies a directory or an archive into the cache, under the name NAME.
- `--to`: copies the dependency NAME out of the cache, to a directory or an archive.
- Use it to add dependencies that the GD++ dependency repository doesn't have, e.g. the API spec of your own Godot build, and to share them.

The cache stores dependencies as directories, with the dependency's layout:

- a spec: a directory with an `extension_api.json` file,
- bindings: a copy of godot-cpp, with its `SConstruct` at the top.

See `gd++ man dependencies`.

# Options

--bind NAME, --spec NAME, --engine NAME
  The kind of dependency, and its name in the cache. Exactly one is required. The name can be any directory name.

--from PATH
  Copy into the cache from PATH: a directory, or with `--tar` or `--zip`, an archive. It goes into the ephemeral cache, or with `--checkin`, the checked in one.

--to PATH
  Copy out of the cache to PATH: a directory, or with `--tar` or `--zip`, an archive. Exactly one of `--from` and `--to` is required.

--checkin
  With `--from`, copy into the checked in cache, `res://_gd++`, instead of the ephemeral one.

--tar
  PATH is a gzip-compressed tarball (`.tar.gz` or `.tgz`) instead of a directory.

--zip
  PATH is a `.zip` file instead of a directory.

# Details

- With `--from`, the contents of the archive or directory become the dependency's directory. An archive holds the dependency's files at its top, not in a subdirectory.
- If the cache already has the dependency, `gd++` asks before overwriting it. Unchanged files are left alone. Files that the new copy lacks are deleted.
- With `--to`, if PATH exists, `gd++` asks before overwriting it. A directory at PATH becomes an exact copy of the dependency.
- If PATH's extension doesn't match `--tar` (`.tar.gz`, `.tgz`) or `--zip` (`.zip`), `gd++` asks whether to use it anyway.
- Archives keep file permissions.
- Archives are written to a temporary file first. So a failure never leaves half an archive behind.
- Archives with entries that point outside of them are refused.

# Examples

Add the API spec of a custom Godot build, and commit it:

```sh
./godot.custom --headless --dump-extension-api
mkdir my-4.7 && mv extension_api.json my-4.7/
gd++ vendor --spec my-4.7 --from my-4.7 --checkin
```

Share bindings with a teammate as an archive, and add them on the other side:

```sh
gd++ vendor --bind 10.0.0-stable --to ~/bind-10.0.0.tar.gz --tar
gd++ vendor --bind 10.0.0-stable --from ~/bind-10.0.0.tar.gz --tar
```

Use a patched godot-cpp checkout as bindings:

```sh
gd++ vendor --bind my-godot-cpp --from ~/src/godot-cpp
gd++ init . --update --bind my-godot-cpp
```
