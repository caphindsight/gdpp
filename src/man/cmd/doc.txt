gd++ doc: look up godot-cpp and GD++ runtime declarations

# Synopsis

```sh
gd++ doc [PKG] NAME
gd++ doc [PKG] NAME.MEMBER
gd++ doc [PKG] [-i]
gd++ doc [PKG] --notifications
```

# Description

Shows the C++ declaration of a name, like `go doc`:

- the class, function, alias or enum, with its comments,
- the header to include,
- its public members,
- the members it inherits, grouped by base class.

Where the names come from:

- godot-cpp: its own helpers, e.g. `TypedArray`, `Ref`, `memnew` or `UtilityFunctions`, which Godot's help doesn't describe, and Godot's classes, e.g. `Node3D`. For what Godot's classes do, see Godot's help, which the output points to.
- The GD++ runtime: the helpers in namespace `gdpp` of the package's runtime header, e.g. `Gd`, `Weak`, `Async` or `create`. See `gd++ man runtime`.
- Where both declare a name, godot-cpp's is shown.

Facts:

- The names come from a package's bindings, generated from its API spec, and from the runtime header of its syntax version. So you see exactly what your code can use.
- PKG is a path in that package. Without it, `gd++ doc` uses the package that contains the current directory.
- The first run in a package may be slow: it generates the bindings. See `gd++ man build-cache`.
- The output goes through the pager when it doesn't fit the terminal, and is highlighted as C++ on terminals. See `gd++ man cli`.

# Arguments and options

PKG
  A path in the package whose bindings to use. Default: the current directory.

NAME
  The name to show, e.g. `TypedArray`, `Node3D`, `Vector3` or `memnew`. Case sensitive.

NAME.MEMBER
  Show only NAME's members called MEMBER, with their comments, e.g. `Array.push_back`.
  - All overloads are shown.
  - If NAME doesn't declare the member, its base classes are searched, nearest first, through aliases too.

-i, --index
  List every type that godot-cpp and the GD++ runtime declare: its kind (e.g. class, struct, enum, template class or alias), its name, and its base class or what it aliases. The default without a name. Not with a name.

--notifications
  List the notifications of each Godot class in the package's API spec, as `on` blocks name them, e.g. `ready` for `on ready { ... }`. Each class is followed by its own notifications, without its bases', one per line, indented by the tab width. Not with a name or `--index`. See `gd++ man callbacks`.

# Output

For a class:

```cpp
#include <godot_cpp/variant/typed_array.hpp> // From godot-cpp.

template <typename T>
class TypedArray : public Array {
  TypedArray();
  void assign(const Array &p_array);
  ...

  // Inherited from Array:
  void push_back(const Variant &p_value);
  ...

  // Inherited from Object:
  ...
};
```

The output reads like a C++ header:

1. The `#include` line you need, with a comment that says where the header comes from:
   - `// From godot-cpp.`: godot-cpp's own headers.
   - `// From the Godot API.`: headers generated from the API spec.
   - `// From the GD++ runtime.`: the runtime header.
2. The declarations, each with the comments right before it in the header.
3. The public members, in braces, indented by the tab width (see `-T` in `gd++ man cli`).
4. The members of each base class, in order, last in the braces.

Facts:

- An alias is followed by the type it aliases, in full.
- For classes generated from the API spec, a last line says "See Godot's help for a description of NAME.".
- With NAME.MEMBER, the `#include` line of the class that declares the member comes first, then the member.

The index lists one type per line:

```cpp
class Array: Object
alias CharString = CharStringT<char>
template class TypedArray: Array
```

The list of notifications has each class, then its notifications, one per line, both sorted by name:

```
CanvasItem:
  draw
  enter_canvas
  ...
Object:
  extension_reloaded
  postinitialize
  predelete
```

# Examples

```sh
gd++ doc TypedArray                  # a godot-cpp helper, and its members
gd++ doc Array.push_back             # one member
gd++ doc Node3D.rotate_y             # a method of a Godot class
gd++ doc UtilityFunctions.print      # what gd::print is
gd++ doc Gd                          # a GD++ runtime helper
gd++ doc tools Ref                   # with the bindings of the package in res://tools
gd++ doc                             # all types
gd++ doc | grep Packed               # all packed array types
gd++ doc --notifications             # the notifications of all classes
```

# Errors

- "There is no name NAME in godot-cpp or the GD++ runtime. Similar names: A, B." The name doesn't exist. Names that contain it, ignoring case, are listed if there are at most 10.
- "Name NAME has no public member MEMBER."
- "Invalid arguments: --notifications cannot be used with a name." `--notifications` lists all classes.
- "Path ... is not contained in a GD++ package, run this in one or pass one, e.g. `gd++ doc PKG NAME`."
- "Failed to find the header ..., run `gd++ clean` to fix this." The build cache is out of date.
