gd++ init: set up projects, packages and classes

# Synopsis

```sh
gd++ init [--vcs none|git] [--presets | --nopresets]
gd++ init PATH --bind NAME --spec NAME [--syntax N | --nightly] [--std STD] [--prefix NAME] [--quit-timeout SECONDS] [--hotreload | --nohotreload] [--macro-depth LEVELS] [--hide DIR...]
gd++ init PATH --update [--bind NAME] [--spec NAME] [--syntax N | --nightly] [--std STD] [--prefix NAME] [--quit-timeout SECONDS] [--hotreload | --nohotreload] [--macro-depth LEVELS] [--hide DIR...]
gd++ init PATH --class NAME (--include PATH | --noinclude) [--icon PATH | --noicon] [--tool | --notool] [--abstract | --noabstract] [--ptr | --ref | --nogdpp] [--update]
```

# Description

`gd++ init` does one of three things, depending on its arguments:

- Without PATH, it sets up GD++ in the project that contains the current directory: it writes `res://.gd++proj`.
- With PATH, it creates or updates the package at PATH: it writes `PATH/.gd++pkg`.
- With PATH and `--class`, it adds or updates a C++ class of the package at PATH.

Output:

- Every change is logged, e.g. "Set the Godot API spec to 4.7.2-stable." or "Set class Spinner to a tool class.".
- If the file already says what you asked for, it warns "No changes were made." and changes nothing.

# Setting up the project

```sh
gd++ init [--vcs none|git] [--presets | --nopresets]
```

Writes `res://.gd++proj`, with the project's settings. See `gd++ man projects`.

--vcs none|git
  The project's version control system.
  - `git`: GD++ writes its blocks of ignores into the `.gitignore` files of the project and every package.
  - `none`: GD++ removes them.
  - See `gd++ man vcs`.

--presets
  Keep GD++'s sources and config files out of exported games. `gd++ build` and `gd++ fix` add GD++'s exclude filters to every preset in `res://export_presets.cfg`. The default. See `gd++ man shipping`.

--nopresets
  Make the next `gd++ build` or `gd++ fix` remove GD++'s exclude filters from every preset. After that, GD++ doesn't touch `res://export_presets.cfg`.

- Without options, it creates `.gd++proj` with the defaults, or reformats it.
- The file is optional. You only need this step to change a setting.

# Creating a package

```sh
gd++ init PATH --bind NAME --spec NAME [--syntax N | --nightly] [--std STD] [--prefix NAME] [--quit-timeout SECONDS] [--hotreload | --nohotreload] [--macro-depth LEVELS] [--hide DIR...]
```

- Creates the directory PATH if needed, and writes `PATH/.gd++pkg`.
- PATH must be inside a project.
- `.` makes the current directory a package, e.g. the project root.
- If the project uses git, it also writes the package-level block into `PATH/.gitignore`.
- If the project's caches lack the bindings or the spec, it warns, and tells you to run `gd++ fetch --missing`.
- `gd++ fetch --index` lists the bindings and specs that exist.

See `gd++ man packages`.

--bind NAME
  The package's Godot C++ bindings, e.g. `10.0.0-stable`. Required for a new package.

--spec NAME
  The package's Godot API spec, e.g. `4.7.2-stable`. Required for a new package.

--syntax N
  The package's GD++ syntax version. Default for a new package: the latest stable one.
  - `gd++ --syntax` lists them all.
  - Syntax 0 is the nightly version, which may break your code at any time. `gd++ init` warns that it should never be used in production.
  - For a version that this `gd++` doesn't know, e.g. `2`, `gd++ init` asks whether to continue: either the value is wrong or `gd++` is outdated.
  - See "Syntax versions" in `gd++ man packages`.

--nightly
  The same as `--syntax 0`.

--std STD
  The package's C++ standard, e.g. `c++17`, `c++20` or `c++23`. Default: `c++20`.

--prefix NAME
  The prefix of the classes that GD++ adds to the package, e.g. `Foo` for `FooAsync`, the class of its tasks. Default: the package's id in PascalCase, e.g. `MyGame` for `my_game`. See `gd++ man async`.

--quit-timeout SECONDS
  How many seconds the package's tasks may still run after the game starts quitting, before it exits anyway, e.g. `2.5`. Default: `1`. See "When the game quits" in `gd++ man async`.

--hotreload
  Make the editor reload the package's library when a build changes it. The default.

--nohotreload
  Make the editor load the package's library only once, e.g. because hot reload crashes the editor. See `hot_reload` in `gd++ man packages`.

--macro-depth LEVELS
  How deeply the package's macro and template invocations may nest, e.g. `100`. Default: `64`. See `gd++ man templates` and `gd++ man macros`.

--hide DIR...
  Hide these directories of the package from Godot, e.g. `src`. See `hide` in `gd++ man packages`.
  - Each DIR is relative to the package root, e.g. `src` or `pkg://src/gen`.
  - Adds them to the package's hidden directories, and keeps the others. `gd++ rm PATH --hide DIR...` removes them.
  - Puts an empty `.gdignore` file into each one that exists.
  - Asks first if a directory doesn't exist yet, or contains another package, which Godot then can't load.


# Updating a package

```sh
gd++ init PATH --update [--bind NAME] [--spec NAME] [--syntax N | --nightly] [--std STD] [--prefix NAME] [--quit-timeout SECONDS] [--hotreload | --nohotreload] [--macro-depth LEVELS] [--hide DIR...]
```

- Changes the given settings of the existing package at PATH, and keeps the others.
- Without `--update`, `gd++ init` asks "Package PATH already exists. Update it?" when PATH is a package already.
- Changing any setting but `--hide` makes the package's next build start from scratch.

--update
  Update an existing package, or with `--class` an existing class, without asking. Fails if it doesn't exist.

# Adding or updating a C++ class

```sh
gd++ init PATH --class NAME (--include PATH | --noinclude) [--icon PATH | --noicon] [--tool | --notool] [--abstract | --noabstract] [--ptr | --ref | --nogdpp] [--update]
```

- Adds the plain C++ class NAME to the `.gd++pkg` of the package at PATH, so the package registers it with Godot.
- Updates the class if it's there already.
- GD++ classes don't need this: GD++ finds them in the GD++ files, and refuses to add them here.

See `gd++ man cpp-classes`.

--class NAME
  The name of the class to add or update. It must be a C++ identifier.

--include PATH
  The header that declares the class, as a `pkg://` or `res://` path, e.g. `pkg://src/spinner.h`. If it doesn't end with `.h` or `.hpp`, `gd++ init` asks you to confirm.

--noinclude
  Remove the class's header, or create the class without one, e.g. when another header already declares it. A new class needs `--include` or `--noinclude`.

--icon PATH
  The class's icon in the editor, as a `pkg://` or `res://` path, e.g. `pkg://icons/spinner.svg`.

--noicon
  Remove the class's icon.

--tool
  Make the class a tool class: its code runs in the editor too, like a GD++ class with `@tool`. Sets `tool = true` in its `[[class]]` table.

--notool
  Make the class a runtime class: in the editor, Godot shows placeholders for its objects, which run none of its code. Removes `tool = true` from its `[[class]]` table.

--abstract
  Make the class only a base for other classes, like a GD++ class with `@abstract`: the editor doesn't offer it. Sets `abstract = true` in its `[[class]]` table.

--noabstract
  Make the class concrete again. Removes `abstract = true` from its `[[class]]` table.

--ptr
  Let GD++ code use the class by name, as a pointer, e.g. `Spinner *`: for classes that aren't refcounted. Sets `kind = "ptr"` in its `[[class]]` table, shown as `[ptr]` by `gd++ ls`. The class needs an include.

--ref
  Let GD++ code use the class by name, as a reference, e.g. `Ref<Spinner>`: for refcounted classes. Sets `kind = "ref"`, shown as `[ref]`. The class needs an include.

--nogdpp
  Stop GD++ code from using the class by name. Removes `kind` from its `[[class]]` table.

Updating a class:

- `--include` and `--icon` change the path. `--noinclude` and `--noicon` clear it. Without either, the path stays.
- `--tool` and `--notool` make it a tool or a runtime class. Without either, that stays.
- `--abstract` and `--noabstract` make it abstract or concrete. Without either, that stays.
- `--ptr`, `--ref` and `--nogdpp` change how GD++ code uses it. Without any of them, that stays.
- Without `--update`, `gd++ init` asks "Class NAME already exists in PATH. Update it?".

A new class:

- is a runtime class, unless you pass `--tool`,
- can't be used by GD++ code, unless you pass `--ptr` or `--ref`.

# Rules

- `--vcs`, `--presets` and `--nopresets` work only without PATH.
- `--presets` and `--nopresets` can't be used together.
- `--update`, `--bind`, `--spec`, `--syntax`, `--std`, `--prefix`, `--quit-timeout`, `--hotreload`, `--nohotreload`, `--macro-depth`, `--hide` and `--class` need PATH.
- `--include`, `--noinclude`, `--icon`, `--noicon`, `--tool`, `--notool`, `--abstract`, `--noabstract`, `--ptr`, `--ref` and `--nogdpp` need `--class`.
- `--bind`, `--spec`, `--syntax`, `--std`, `--prefix`, `--quit-timeout`, `--hotreload`, `--nohotreload`, `--macro-depth` and `--hide` can't be used with `--class`.
- `--quit-timeout` and `--syntax` can't be negative.
- `--macro-depth` must be positive.
- `--syntax` and `--nightly` can't be used together.
- `--include` and `--noinclude`, `--icon` and `--noicon`, `--tool` and `--notool`, `--abstract` and `--noabstract`, and `--ptr`, `--ref` and `--nogdpp` can't be used together.
- `--ptr` and `--ref` need a class with an include.

# Examples

A project with git, and one package at its root:

```sh
gd++ init --vcs git
gd++ init . --bind 10.0.0-stable --spec 4.7.2-stable
gd++ fetch --missing
```

A second package, with C++17:

```sh
gd++ init tools --bind 10.0.0-stable --spec 4.7.2-stable --std c++17
```

Upgrade a package to a newer spec:

```sh
gd++ init . --update --spec 4.8-stable
gd++ fetch --missing
```

Hide the package's C++ sources from the Godot editor:

```sh
gd++ init . --update --hide src
```

Register a C++ class, then give it an icon, then remove the icon:

```sh
gd++ init . --class Spinner --include pkg://src/spinner.h
gd++ init . --class Spinner --update --icon pkg://icons/spinner.svg
gd++ init . --class Spinner --update --noicon
```

Register a C++ class whose code runs in the editor too, then make it run only in the game:

```sh
gd++ init . --class Gizmo --include pkg://src/gizmo.h --tool
gd++ init . --class Gizmo --update --notool
```

Let GD++ code use a C++ class that extends `Node3D`, then stop it:

```sh
gd++ init . --class Spinner --update --ptr
gd++ init . --class Spinner --update --nogdpp
```

# Errors

- "Invalid arguments: --bind and --spec are required for a new package."
- "Invalid arguments: a new class requires --include or --noinclude."
- "Invalid arguments: GD++ code can only use class NAME if it has an include." `--ptr` or `--ref` on a class without one.
- "Class NAME is declared in FILE, so it can only be changed there." It's a GD++ class.
- "There is no class NAME in PATH." With `--update`, the class must exist.
- "Invalid arguments: DIR is not a directory inside the package." `--hide` takes paths inside the package, e.g. `src`.
- "Path ... is not contained in a Godot project." Run it inside a project.
