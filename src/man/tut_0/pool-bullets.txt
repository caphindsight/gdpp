Tutorial: reuse bullets with an object pool

A game that fires many bullets creates and deletes nodes all the time. Each new bullet allocates memory, and Godot sets up the node and all its children. An object pool avoids this: instead of deleting a bullet, it keeps it, and reuses it for the next shot.

This tutorial builds bullets that hit enemies, deal damage and destroy themselves, then turns them into a pool. It assumes a project that builds, as in `gd++ man tour`.

# The example

- A gun fires bullets.
- A bullet flies straight ahead.
- When it hits an enemy, it deals damage and destroys itself.
- If it hits nothing, it destroys itself after two seconds.

# 1. Make the bullet's scene

In the editor, make a scene `bullet.tscn` in the package. Its root is an `Area3D`, with a `MeshInstance3D` and a `CollisionShape3D` as children. Then write the `Bullet` class:

```gd++
@scene("pkg://bullet.tscn")
class_name Bullet
extends Area3D

@export var speed: float = 40.0
@export var damage: int = 10
@export var lifetime: float = 2.0

var age: float = 0.0

on physics_process(delta: float) {
  translate(Vector3(0, 0, -speed * delta));
  age += delta;
  if (age >= lifetime) {
    queue_destroy this;
  }
}

on this.body_entered(body) {
  Gd<Enemy> enemy = body as Gd<Enemy>;
  if (enemy) {
    enemy->take_damage(damage);
    queue_destroy this;
  }
}
```

A bullet destroys itself when it hits an enemy or its lifetime runs out. Step 2 explains how.

1. Build the package.
2. Change the type of the scene's root to `Bullet`.

`on this.body_entered` runs when the bullet's own `body_entered` signal fires, with its argument, a `Node3D`. No connection in the Node dock is needed. See "Connecting to signals" in `gd++ man signals`.

`@scene` makes `create Bullet` instantiate `bullet.tscn`. So each bullet comes with its mesh and collision shape. See "@scene" in `gd++ man classes`.

The enemy takes the damage:

```gd++
class_name Enemy
extends CharacterBody3D

@export var health: int = 100

func take_damage(amount: int) -> void {
  health -= amount;
  if (health <= 0) {
    queue_destroy this;
  }
}
```

# 2. Destroy the bullet safely

The bullet uses `queue_destroy` rather than `destroy`, for two reasons:

- `body_entered` comes in the middle of the physics engine's work, which doesn't allow removing a collision object from the tree.
  - `queue_destroy` is like Godot's `queue_free`: it destroys the node at the end of the frame, when that's safe.
  - Unlike `queue_free`, it works with pools: a pooled bullet goes back to its pool instead of being freed. See `gd++ man classes`.
- A bullet can hit two enemies in the same frame, or hit one just as its lifetime runs out.
  - Then it queues its destruction twice, which is fine.
  - The second time does nothing, since the bullet is already gone, or already back in its pool.

# 3. Fire bullets

The gun creates a bullet, adds it to the level, and places it at the gun's muzzle:

```gd++
class_name Gun
extends Node3D

func fire() -> void {
  Gd<Bullet> bullet = create Bullet;
  get_tree()->get_current_scene()->add_child(bullet);
  bullet->set_global_transform(get_global_transform());
}
```

- The bullet is added to the level, not to the gun, so that it doesn't move with the gun.
- Run the game: bullets fly, hit enemies, and disappear.
- For now, `queue_destroy` deletes each bullet, and `create` makes a new one for each shot.

# 4. Pool the bullets

Add `@pool` to the class:

```gd++
@pool
@scene("pkg://bullet.tscn")
class_name Bullet
extends Area3D
```

Nothing else changes: `create` and `queue_destroy` already handle pools.

- `queue_destroy` doesn't delete the bullet any more. It removes the bullet from the tree, and keeps it in the pool.
- The next `create` reuses it.
- The pool only instantiates the scene when it has no bullet to reuse.
- A bullet out of the tree gets no `_physics_process` and no collisions. So a bullet waiting in the pool costs nothing.

See `gd++ man pools`.

# 5. Reset reused bullets

Run the game again, and fire a few times: the bullets of later shots disappear right away.

- A reused bullet keeps its variables: `age` is still past its `lifetime`.
- Variables get their initial values only when an object is actually created, not when it's reused.

Mark `age` with `@recycle`, which resets a variable to its initial value each time the pool reuses an object:

```gd++
@recycle var age: float = 0.0
```

The exported variables don't need it: nothing changes them while a bullet flies. So a reused bullet still has the values from its scene. See "Resetting variables" in `gd++ man pools`.

To see the pool at work, print a line in the plain `ctor`:

```gd++
ctor {
  gd::print("A new bullet.");
}
```

- The first shots print it.
- Once enough bullets are in the pool, firing prints nothing: every shot reuses a bullet.

# 6. Limit the pool's size

`@pool` has no limit. If the gun fires faster than bullets expire, the pool creates as many bullets as needed. To cap the number of bullets, give the pool a size:

```gd++
@pool(200)
```

- Now the pool holds up to 200 bullets, counting those in use and those waiting in the pool.
- Once all 200 are in use, `create` returns `nullptr`. So the gun must check for it:

```gd++
func fire() -> void {
  Gd<Bullet> bullet = create Bullet;
  if (!bullet) {
    return;    // Too many bullets in flight: skip this shot.
  }
  get_tree()->get_current_scene()->add_child(bullet);
  bullet->set_global_transform(get_global_transform());
}
```

- Using the null pointer instead would crash the game.
- To have more bullets rather than skip a shot, write `@pool(200, "grow")`. The pool then grows past 200 bullets, and only logs an error about it in debug builds, so you can raise the number.

# 7. Fill the pool when the level loads

The pool still makes the first 200 bullets during the first shots. To make them while the level loads instead, add `@factory_pool` next to `@pool(200)`. It gives `Bullet` the static method `pool_reserve`. Call it in the level's script, and free the bullets again when the level is unloaded:

```gd++
@pool(200)
@factory_pool
```

```gdscript
func _ready() -> void:
    Bullet.pool_reserve()    # 200 bullets, the size of the pool

func _exit_tree() -> void:
    Bullet.pool_reserve(0)
```

- Without a count, `pool_reserve` makes as many bullets as the size in `@pool(200)`. So the number lives in one place.
- Now every shot reuses a bullet: the plain `ctor` prints its lines while the level loads, and never during the game.
- To drop all the bullets at once, also those in flight, e.g. when the player quits to the menu, call `Bullet.pool_clear()`, the other method of `@factory_pool`.

# 8. Measure

A pool pays off when objects come and go often. To see what it saves, put `@profile` on `fire`, and build with profiling on:

```gd++
@profile
func fire() -> void { ... }
```

```sh
gd++ build --opt --profile all --print
```

Compare the time of `fire` with and without `@pool`. See `gd++ man optimize`.
