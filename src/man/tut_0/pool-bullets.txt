Tutorial: reuse bullets with an object pool

A game that fires many bullets creates and deletes nodes all the time: each new bullet allocates memory, and Godot sets up the node and all of its children. An object pool avoids this: instead of deleting a bullet, it keeps it, and reuses it for the next shot. This tutorial builds bullets that hit enemies, deal damage and destroy themselves, and then turns them into a pool. It assumes a project that builds, as in `gd++ man tour`.

# The example

A gun fires bullets. A bullet flies straight ahead. When it hits an enemy, it deals damage and destroys itself. If it hits nothing, it destroys itself after two seconds.

# 1. Make the bullet's scene

In the editor, make a scene `bullet.tscn` in the package. Its root is an `Area3D`, with a `MeshInstance3D` and a `CollisionShape3D` as children. Then write the `Bullet` class:

```gd++
@scene("pkg://bullet.tscn")
class_name Bullet
extends Area3D

@export var speed: float = 40.0
@export var damage: int = 10
@export var lifetime: float = 2.0

var age: float = 0.0

func _physics_process(delta: float) -> void {
  translate(Vector3(0, 0, -speed * delta));
  age += delta;
  if (age >= lifetime) {
    queue_destroy this;
  }
}

func _on_body_entered(body: Node3D) -> void {
  Enemy *enemy = body as Enemy *;
  if (enemy) {
    enemy->take_damage(damage);
    queue_destroy this;
  }
}
```

A bullet destroys itself when it hits an enemy or its lifetime runs out. Step 2 explains how.

Build the package, and change the type of the scene's root to `Bullet`. Connect its `body_entered` signal to `_on_body_entered` in the Node dock. `@scene` makes `create Bullet` instantiate `bullet.tscn`, so each bullet comes with its mesh and collision shape. See "@scene" in `gd++ man classes`.

The enemy takes the damage:

```gd++
class_name Enemy
extends CharacterBody3D

@export var health: int = 100

func take_damage(amount: int) -> void {
  health -= amount;
  if (health <= 0) {
    queue_destroy this;
  }
}
```

# 2. Destroy the bullet safely

The bullet uses `queue_destroy` rather than `destroy`, for two reasons:

- `body_entered` comes in the middle of the physics engine's work, which doesn't allow removing a collision object from the tree. `queue_destroy` is like Godot's `queue_free`: it destroys the node at the end of the frame, when that's safe. Unlike `queue_free`, it works with pools: a pooled bullet goes back to its pool instead of being freed. See `gd++ man classes`.
- A bullet can hit two enemies in the same frame, or hit one just as its lifetime runs out. Then it queues its destruction twice, which is fine: the second time does nothing, since the bullet is already gone, or already back in its pool.

# 3. Fire bullets

The gun creates a bullet, adds it to the level, and places it at the gun's muzzle:

```gd++
class_name Gun
extends Node3D

func fire() -> void {
  Bullet *bullet = create Bullet;
  get_tree()->get_current_scene()->add_child(bullet);
  bullet->set_global_transform(get_global_transform());
}
```

The bullet is added to the level, not to the gun, so that it doesn't move with the gun. Run the game: bullets fly, hit enemies, and disappear. For now, `destroy` deletes each bullet, and `create` makes a new one for each shot.

# 4. Pool the bullets

Add `@pool` to the class:

```gd++
@pool
@scene("pkg://bullet.tscn")
class_name Bullet
extends Area3D
```

Nothing else changes: `create` and `destroy` already handle pools. Now `destroy` doesn't delete the bullet. Instead, it removes the bullet from the tree and keeps it in the pool, and the next `create` reuses it. The pool only instantiates the scene when it has no bullet to reuse. A bullet that's out of the tree gets no `_physics_process` and no collisions, so a bullet waiting in the pool costs nothing. See `gd++ man pools`.

# 5. Reset reused bullets

Run the game again, and fire a few times: the bullets of later shots disappear right away. That's because a reused bullet keeps its variables: `age` is still past its `lifetime`. Variables get their initial values only when an object is actually created, not when it's reused.

Mark `age` with `@recycle`, which resets a variable to its initial value each time the pool reuses an object:

```gd++
@recycle var age: float = 0.0
```

The exported variables don't need it: nothing changes them while a bullet flies, so a reused bullet still has the values from its scene. See "Resetting variables" in `gd++ man pools`.

To see the pool at work, print a line in the plain `ctor`:

```gd++
ctor {
  gd::print("A new bullet.");
}
```

The first shots print it. Once enough bullets are in the pool, firing prints nothing: every shot reuses a bullet.

# 6. Limit the pool's size

`@pool` has no limit: if the gun fires faster than bullets expire, the pool creates as many bullets as needed. To cap the number of bullets, give the pool a size:

```gd++
@pool(200)
```

Now the pool can hold up to 200 bullets, counting both those in use and those waiting in the pool. Once all 200 are in use, `create` returns `nullptr`, so the gun must check for it:

```gd++
func fire() -> void {
  Bullet *bullet = create Bullet;
  if (!bullet) {
    return;    // Too many bullets in flight: skip this shot.
  }
  get_tree()->get_current_scene()->add_child(bullet);
  bullet->set_global_transform(get_global_transform());
}
```

Using the null pointer instead would crash the game. If running out of bullets is a bug, write `@pool(200, "strict")`: then a full pool also logs an error.

# 7. Measure

A pool pays off when objects come and go often. To see what it saves, put `@profile` on `fire`, and build with profiling on:

```gd++
@profile
func fire() -> void { ... }
```

```sh
gd++ build --opt --profile all --print
```

Compare the time of `fire` with and without `@pool`. See `gd++ man optimize`.
